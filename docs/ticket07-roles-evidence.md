## Ownership And Durability

One workbench domain owns version-1 associations; the additive optional `creation.cwd` field preserves old records. Each structural key is serialized independently. New creation requires Kaogong's explicit absolute `roleCwd`; omission permits reading existing ready bindings but never defaults new creation to process cwd. The intent captures cwd before native create, so config changes/restarts cannot change a pending identity's location. A legacy intent without creation location can only adopt a native Session whose public inspection establishes cwd; otherwise explicit replacement is required.

Native blank Session creation is lazy and is not a durability barrier. After exact-ID/preset native create, the Host awaits public `ctx.sessionPersistence.flush()` before persisting ready. This service-wide barrier materializes headers and drains all active native write handles; it can incur writes for other active Sessions, but creates no turn. Failure leaves the original intent ID retryable. No backend/private write, guessed replacement, cancel, archive or deletion is used. Already-ready missing Sessions remain explicit same-ID errors.

Client owners and command busy/error state are per complete key. Every opened role pane remains mounted while inactive, when switching app pages, and when the existing workbench hides/minimizes/closes its window. Native composer owns drafts by exact Session; this plugin adds no fake draft owner. UI refs and `sessions.using` command refs are independent, with command lifetime extending through send settlement. Registration disposal ends owners; browser layout persistence is not conversation persistence. Refresh/restart require native history/draft behavior and remain runtime gates.

Running, pending interaction and completion unread facts come from official `useSessionStatus` keyed by exact Session ID. Native history/send/Agent failures come from `useSession`. The plugin does not fabricate approval or unread state, or change main-view acknowledgement ownership. Material/result JSON slashes remain literal Unicode escapes so only the intended declared Skill gesture is scanned. Non-JSON/auth/missing service responses remain local explicit errors.

## Durable Ownership

`Lessons` in `plugins/kaogong/src/lessons.ts` owns one serialized command queue. The existing Host opens the additive version-1 `kaogong_lessons` domain exactly once, closes acceptance and awaits that queue before draining the existing PracticeRounds owner and closing domains. There is no second scorer, draft owner, role engine or native conversation owner.

Each aggregate has a learner-supplied stable UUID, a confirmed objective, stable objective/homework IDs, default-instance ownership, explicit subject/optional knowledge point, material ID/title/source/version references, optional legacy note ID/version, up to twenty linked submitted rounds, bounded learner notes and an optional completion receipt. The deliberately small first workflow is one practice homework task per lesson: submit at least one fully answered matching round, optionally save all incorrect-question reasons, then confirm. Arbitrary subjective/manual homework and multi-stage orchestration are not implemented.

The domain global stores the selected classroom ID. Aggregate creation precedes selection persistence; these are not an invented transaction. A failed pointer write leaves the aggregate intact, and retrying the same creation ID repairs selection without duplication. Missing selected records report an error rather than silently selecting a replacement. Reads and registration never create Sessions or call models.

## Host Evidence And UI

Routes are POST JSON under `/api/kaogong/lesson/`: `create`, `list`, `read`, `current`, `select`, `link`, `summary`, `confirm`, `prepare`. All use the official connection rejection/authentication/same-origin/platform guard and no-store JSON. Request parsers reject extra score/completion fields. `create` takes lessonId, subject, objective, optional knowledgePoint, materialIds, requireReflections and optional legacyNoteId. `link` accepts only lessonId/roundId; `confirm` accepts only lessonId/confirmed:true. There is no model completion tool.

`link`, read and confirmation resolve rounds through ticket08's existing authority. Unsubmitted/empty/missing rounds, foreign subject and mismatching explicit knowledge-point evidence reject. Skipped answers cannot complete homework; required wrong-question reasons must be persisted through the original reflection path. The final completion receipt records confirmation time and actual round/question/reflection IDs/counts in one lesson write. Identical create/link/confirmation retries do not create additional evidence; conflicting creation contents reject. Later rounds require a new explicit lesson after completion; no accuracy threshold claims mastery.

Saved prose remains explicitly learner notes and cannot set completion. Manual plan flags, original notes, question IDs, materials and all prior domains remain unchanged. Durable score and pending notebook projection are reported separately: score-only homework may complete with projection pending. The original `ready/sending/sent` counselor receipt is reused unchanged; sent is not counselor-response evidence and sending is not auto-resend authorization.

The classroom UI supports creating a confirmed objective, referencing current material/an old note ID, starting homework through the existing practice owner, attaching the current submitted round, saving notes, explicitly confirming and selecting/resuming a persisted classroom. Browser state retains only shared unsent form/summary drafts and pending commands; accepted lesson/task/evidence/selection lives on Host. Refresh re-reads Host truth and does not overwrite an unsaved shared summary draft. Browser-only practice drafts retain ticket08's documented limitations.

## Identity And Shared Summary

The aggregate retains the exact 07 subject-teacher structural key. Explicit continuation calls read-only `prepare`, then the existing public role ensure, then prepare again to capture a ready ID/preset before sending through the existing native teaching action. Once captured, missing/replaced/pending identity rejects continuation; it never copies the legacy subjectless teacher into a subject key. An explicit new classroom remains available; automatic rebinding is not implemented. The original role command lifetime, mounted native panes, no-cancel behavior, stale/archive checks and JSON slash escaping remain owned by unchanged 07 code.

`kaogong_lesson_read` lists real classroom IDs or reads a bounded summary with objective/task/material references, same role attribution, real attempt counts, reflection/projection/review status, learner-confirmed completion and next action. Roles can read that shared app evidence; raw Session histories, original material bodies, per-question answers and source paths are not copied into it. Explicit continuation supplies that summary as untrusted material through the existing TeachingEvidence path, where 07 encodes slashes before native user sending. There is no separate automatic cross-role sender or competing counselor review receipt.

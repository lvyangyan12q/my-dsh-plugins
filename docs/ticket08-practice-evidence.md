# Ticket 08 Practice Rounds And Counselor Evidence

Candidate based on `9868616`, branch `codex/practice-rounds`. This implements ticket 08 only. Chrome and live native-turn acceptance remain pending.

## Application Behavior

`practice-rounds.ts` owns one application command queue shared by HTTP, the existing practice tools and native notebook record/delete commands. Manual notebook edits retain practice ownership markers. The additive version-1 `kaogong_practice.rounds` domain stores issued IDs, original bank snapshots, scope, cycle history, one scored answer set, round reflections, projection progress and the counselor handoff receipt. Existing bank/notebook/progress/knowledge domain names and versions remain unchanged. Three optional notebook fields identify the latest projected round, submission sequence and reflection revision; legacy notebook records remain valid.

Each round issues ten distinct approved objective questions when ten are available. A smaller bank returns its actual count. Continuing a submitted round prioritizes unseen IDs, fills the end of the cycle without duplicates inside the round, and then cycles. Subject filters also constrain explicit knowledge-point selection. A plan topic with no matching questions retains the existing subject fallback. Original question IDs, options, correct answers, source and image association stay unchanged. Known answer-key/analysis markers in material, options or source fail closed; unsupported subjective questions are excluded from automatic scoring. Nothing reparses PDFs or modifies bank text.

Before submission, start/read/history/tool responses contain no correct-answer or explanation fields. The issued snapshot is authoritative even if the bank subsequently changes. Submission requires the issued round ID and every member exactly once; empty answers are skipped, foreign/missing/duplicate IDs and invalid option values reject before writes. Identical normalized retries reuse the saved score; different answers return an explicit HTTP 409. Tools require the same round ID and call the same scorer. Caller-provided counts, result prose and browser caches never supply a score.

The score is durable before notebook projection begins. Projection is deliberately not an atomic multi-record transaction. A failed row or projection-marker write leaves `projection: pending`; startup, read and identical retry recover it. Atomic public table updates preserve existing creation time, notes and error reasons, skip already-applied revisions, and do not overwrite newer attempts or later manual edits. Reason-only reflection changes do not reapply older saved notes. Round reflections are stored before projection, validated against the submitted members and retained independently of later attempts. Identical reflection retries create no additional history records.

The Client caches only a round pointer and learner answer/reflection drafts under `kaogong/default/practice-draft/v1`. After refresh, it reloads the issued round and score from the Host. Cached scores are ignored. Storage failure is visible; this is browser-local draft recovery, not multi-device persistence. Practice history reloads earlier issued/submitted rounds. A synchronous shared command owner prevents duplicate commands across view transfer. Pending requests survive close/provider changes as before.

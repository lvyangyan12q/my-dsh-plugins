## Contract

- `PersonalWorkbenchBindings.listRoles()` returns current app-owned declarations. Optional `RoleDefinition.display` accepts a name, declared source and official bundle name; these are display metadata, not native model/permission configuration. Withdrawal preserves bindings and assignments. Existing registration/ensure/retry/replace semantics are unchanged.
- POST `/api/personal-workbench/management` accepts only `{ action: 'catalog' }` or `{ action: 'assign', key, expectedRevision, names }`. Authentication/same-origin checks precede parsing; JSON, method, size, key/name grammar, unique names and revision checks are enforced. Missing optional authorities return 503. Saves are serialized by complete role key and reject stale revisions. Read/save never creates or sends a Session.
- Workbench-owned `personal_workbench_management` version-1 domain stores only complete keys, revisions and existing Skill names. It is independent of the 07 association domain and all Kaogong domains. No bodies, credential/config objects, native settings, or presumed loaded flags are persisted.
- Catalogs resolve declared presets separately from native Skill metadata. Ready bindings must match the exact recorded Session/preset; missing, archived, interrupted and conflicting Sessions stay explicit. Live reads use the real Agent scope and preset-local service when present. Cold reads acquire/release the preset scope with the recorded cwd; uncreated roles require the declared creation cwd. Incomplete snapshots cannot authorize assignment. No global fallback serves as role evidence.
- The global Agent catalog excludes presets already owned by declared app roles. Roles are grouped under the registered app, using its Client role labels. Skill metadata is allowlisted from native snapshots: name, description, source, provider and invocation policies. Application ownership is reported only where a declaration supplies the same teaching name/provider; otherwise it remains undeclared. No self-built/community provenance is inferred from preset names.
- Tools come from scoped public `schemas(scope)`. These are visible capabilities, not grants. Native permission projection, live SandboxPolicy.resolve/overrideOf and ApprovalService.overrideOf/config distinguish actual values, Session overrides and composition defaults; absent facts remain unavailable. No private execution or approval method is used.
- Model display comes from the exact Session's `modelSelection.lastUsed/next`. Missing selection is not fabricated. The workbench does not call modelCatalog automatically: that API may perform provider I/O. Full provider catalogs and model selection stay with native DSH controls. The management configuration command uses only optional official `pluginNavigation.openBundle`; unavailable navigation is explicit. No guessed settings panel, shortcut invocation, credentials form or model-default write exists.

## Native Next-Turn Assignment

The management owner registers one public `agent/pre-step` adapter with prepend ordering. On the first step of a claimed direct-user turn, it finds exactly one currently registered ready role by the actual Agent/Session ID, verifies the native preset projection and snapshots assigned names in that role's live scope. It checks native snapshot completeness and user invocation policy. Other Sessions, non-user context and continuation steps are not transformed. Assignments are references to the current winning native provider, not pinned body versions.

The adapter supplies `/name` text gestures on the existing claimed user's message, preserving its ID, source and original content blocks. It temporarily replaces that entry in the public mutable claimed-batch array while invoking the downstream waterfall, and restores the original entry in `finally`. Native tool-skill scans that shared payload and alone calls SkillRegistry.get, checks the loaded definition's invocation policy, renders its instructions and supplies canonical skill-invocation messages. The admitted decision preserves the added gestures for user-record provenance. No new user message/source, copied body, synthetic skill-invocation source, second loader, repeated tool-skill apply, preset reconfiguration or alternate Agent engine is introduced.

This addresses the sidecar's identified ordinary-composer gap with tested behavior, rather than treating saved names as activation. It also explicitly depends on rc.2's mutable shared waterfall payload and listener ordering. Adding names only to the returned decision would not work. This is a controlled same-process plugin adapter, not an official registry assign API; compatibility outside the tested rc.2 build is not claimed.

Downstream rejection stays rejection. Cancellation, missing/disabled assignments, provider disappearance, incomplete snapshots, changed presets and absent native loader cannot become successful loads. The adapter requires native instruction messages for all assigned names before returning enter; failure surfaces through native turn errors. Active runtime callbacks and HTTP/saves drain before their domain closes. Later user turns reload through native invocation; unassignment stops future added gestures and does not erase previous instructions or explicit user slash commands. Steering within an already-open continuation is not a new user turn.

The UI separates discovery/assignment from committed native instruction history. Only inspected native user/message records with skill-invocation instructions and nonempty text appear as historical load evidence, with Session event seq. Preflight, save, prompt receipt and a pre-step proposal do not create such history or establish permanent activation. Native model-driven tool loads are not separately summarized by this first history projection.

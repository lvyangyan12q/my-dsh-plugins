## Resolution

客户端实施已完成，真实宿主最终产物验收仍由 04 记录，不能将本工单自动化结果外推为宿主通过。

- 使用布局专用受认证接口；固定目录恢复入口沿用目录选择及绝对路径手工输入，保留稳定项目身份，并核对规范化后的既有目录登记。
- 内容和全部尺寸通过原分栏引擎提交同步快照；按目录防抖、串行修订写入；关闭/切换时提交原项目待保存快照，异步结果不替换其他项目；错误不初始化或覆盖磁盘文件。
- 可见正在保存/已保存/失败/冲突，保留草稿重试；冲突覆盖需明确确认，放弃草稿与重新载入单独操作。旧文件候选显式选择，目录更改先处理原目标。
- TDD 红绿记录：首次运行控制器测试因模块尚未实现失败，随后通过；普通重开误授权冲突草稿、重试读取期间旧草稿覆盖新编辑、目录别名识别分别先出现失败用例再修复。
- 自动化：客户端公开控制器与实际磁盘往返 9/9；最终客户端 bundle 分栏锚点/文件几何/左列标签/尺寸保存 10/10；widget 26/26、details 30/30、input 15/15、session 21/21；构建通过。实际临时目录读写需解除运行沙箱对临时布局目录的限制，未操作正式项目。

### 独立两轴复审后的修正

- 将目录更改、预设调整和新建项目集中到实际工作台调用的公开布局动作协调器。延迟读写期间反复捕获最新项目快照；原目录未保存则拒绝切换；异步结果不关闭后来打开的其他项目，关闭新建弹窗后不再登记或打开项目。
- 文件恢复的终端只恢复标签，显式点击“启动终端”后才创建进程。新选终端保留原启动行为；仍挂载的缓存终端不因重新读取文件而重启。启动许可为运行时状态，不进入布局文件。
- 共用左列/顶行/主行枚举，补齐第二左窗的任务编号、产物绑定和标注捕获/解析。
- 红绿证据：首次实测复现旧代码的4个延迟动作故障、第二左窗的2个身份故障；“原目录保存失败仍切换”的公开动作测试先失败后通过。最终公开布局动作7例、终端React行为2例、标注3例已纳入 test:layout 和打包门禁；test:layout 合计33/33，最终bundle锚点11/11、widget27/27、details30/30。最终实际宿主结果继续由04记录。
- 定向复审补修：目录恢复也通过同一公开协调器执行，同时锁定导航和目录选择两种代次，在读取、规范目录核对、旧文件迁移和登记前检查。切换手动/原生选择目录后，旧目标不再登记或打开。补充4个恢复动作回归，公开动作现为11/11、test:layout为37/37；bundle锚点11/11与widget27/27再次通过。

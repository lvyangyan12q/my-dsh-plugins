# 原生提问分栏宽度补修

实际0.9.5中，1280px页面扣除原生侧栏后可用1000px，工作台比例默认把原生对话压到300px。原生问题卡片overflow隐藏使提交按钮右边界超出卡片，两次点击未提交；手动把原生列放宽到360px后立即提交成功。原生会话仍在执行，修复过程不重启宿主。

0.9.6只调整工作台几何：桌面默认、旧持久宽度、拖动与渲染共用至少360px原生列边界，同时保留声明的模块最小宽度。若空间不足以同时容纳两者，沿用已有的全宽模块/原生对话切换及inert/焦点恢复契约。没有原生DOM样式覆盖、宿主源码修改或用户存储整对象迁移；其他布局持久项保留。

[源码证据](evidence/19-native-question-width-source096.json)：实际构建客户端splitStore.open的旧300px行为先RED，随后default/旧存300/drag、工作台min及其他布局持久项GREEN；原八锚点与新增一场景9/9。实际React客户端回调验证780px空间不足及原444px移动切换/焦点/草稿契约。源码与构建通过不代表原生问题提交真实闭环通过。

待root唯一入口冻结0.9.6并实际安装，在原生提问中验证默认/旧存/拖动后的提交按钮完整且可点击，再检查窄屏模块/原生切换。0.9.5冻结资产、Notes021/Reading022包和SDK声明未改。此补修及父19保持OPEN；不改变历史172或主STATUS。

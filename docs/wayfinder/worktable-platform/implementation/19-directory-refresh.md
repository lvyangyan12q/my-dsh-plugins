# 19: 应用目录刷新补修

实际0.9.4 alpha.2 UI发现：项目应用目录已经挂载时，将一个未归属实例显式关联到该项目，原目录仍显示“新建实例”；返回再重开才显示“继续最近实例”。原实例与两视图身份未丢失，问题是目录快照未响应既有 `dsh:applications-changed` 事件。

0.9.5源码修复：既有目录订阅该事件并重新读取公开 applications 目录；切换项目或卸载时取消读取，旧响应不得覆盖新项目/新快照。点击主入口前重新查询当前项目 latest：原来显示“新建实例”的陈旧按钮会恢复刚关联实例；用户明确选择“新建独立实例”仍创建新的独立实例。没有轮询、原生修改、默认移组或模型发送。

TDD接缝：真实React `ApplicationPicker` 挂载、公开fetch请求/响应、窗口变更事件、按钮及 `onOpen` 身份。首条事件刷新回归先红；修复后绿。第二条陈旧新建点击先红（产生重复实例），随后latest复核转绿。补验迟到请求、项目替换、卸载监听清理、明确独立新建。既有服务端目录与组件回归一起执行。

[源码验证记录](evidence/19-directory-refresh-source.json)仅证明源码/构建接缝，不能替代最终包实际UI。0.9.4冻结资产未改；未打包、安装、重启、修改3093或正式3080；考公仍暂停。

待root：唯一入口冻结新版本后真实重放“保持原目录挂载→另一入口关联未归属实例→原目录自动出现继续→打开原实例/原视图”，再验证明确独立新建及刷新恢复。此补修票和19保持open，不能据277源码/10factory关闭实页验收。

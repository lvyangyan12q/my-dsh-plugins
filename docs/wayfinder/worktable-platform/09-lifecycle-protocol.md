# 09：应用生命周期与产品降版

状态：最终0.5.0已在独立3091完成真实官方安装、停用、升级、回退及离线卸载重装验收，09已关闭；见下方最终证据，源码辅助检查不替代真实操作。

## 应用级开关

ApplicationDirectory.setEnabled(appId, enabled, expectedRevision) 在现有 AdmissionGate 与配置 owner 内串行发布。描述符返回 enabled 与 lifecycleRevision；陈旧版本报 revision-conflict，不覆盖较新策略。未写策略默认启用。停用记录不删除应用、实例、视图、共享授权或角色/任务引用。

停用阻止 createInstance、TaskDirectory.prepare 和尚无 requestId 的 submit。两次提交前复验包含该开关；与原生准入共用已有线性化门闩，已经进入准入的任务先结算，开关不能越过它伪称之前已拒绝。开关本身不调用原生 Stop，不更换会话或自动重发。角色创建/重试及替换进入原生创建前也要求应用可用。

继续现有实例允许打开停用反馈与独立原生会话交接，不授予新任务权限。应用入口显示停用和显式启用按钮；缺失插件的策略仍可显式启用，但这不安装插件。普通网页没有新原生权限。

## 会话交接不依赖应用组件

长期存在的平台任务服务从持久 task/role 记录列交接目录。openSession/stopSession 只接受这些记录中的会话：有 requestId 的任务会话或角色当前/历史会话；任意客户端 sessionId 不在目录时拒绝。没有新 prompt、steer、followup 或 composer。当前应用定义、公共 Agent/Skill 停用或私有能力撤销均不能改变旧会话身份。

已登记 viewId 的 list/open/Stop 用 resolveStoredView 读取耐久 view→instance 身份，不依赖应用贡献仍然注册；跨实例 taskId 仍拒绝。新的准备和发送继续用当前定义、角色、资料授权和开关门禁。角色交接列只读取持久引用，不重新校验能力或创建会话。原生问题、审批、轨迹和 Stop 继续使用 DSH 原生入口；Stop 是会话当前回合，保留队列，不回滚已有写入，不证明任务成功。

应用目录以及停用实例显示“原生会话交接 / 卸载准备”，用户可显式打开原生对话或请求 Stop。清单仅表示可找到引用，不表示任务已结束、问题/审批已处理或交接已完成。先打开原生对话处理这些状态，再执行卸载。

## 官方管理器边界

原生 plugin-manager 的 enable/remove 接口没有业务任务异步否决 hook；不能宣称本插件可拦住用户直接停用或卸载。直接卸载应用贡献保留平台目录与原生会话交接；直接卸载整个 Worktable 会移除本交接 UI，此时使用已保留的 DSH 原生会话列表和原生控制。没有修改官方管理器、取消任务或删除业务数据的卸载副作用。

本轮不新增无法证明的自动“任务已安全处理”勾选。实际验收需分别记录应用级开关与官方插件停用/卸载，不能以自有按钮通过代替官方路径通过。原生进程终止后的待答问题恢复能力限定于 08 的真实证据，不承诺重建未恢复的原生待答状态。

## 可逆配置与兼容回退

产品版本候选为 0.5.0，应用接入协议仍为 1；原生 rc.2 不变。平台应用配置只有在存在至少一条 disabled 策略时使用 schema2；09 明确接受 schema1/2，严格验证 schema 与策略一致。只有用户显式启用全部策略才改回 schema1。绝不为降版静默启用、删除策略或清空记录。原子发布失败保留原字节和旧策略，显式重试。

08 最终产品 0.4.0（Worktable SHA256 c05049edcaccd43e42baff90f18311fe85457b38963ade6ea03a393b964fe5ac，Reading SHA256 639c6964e471ba7e3c53e4d6ae14874eea63c77671087d36198190a9fd41ba41）是配置为 schema1 时的兼容回退基线。旧版遇 schema2 必须拒绝相关读写并保留源文件；不是“回退后忽略停用”。重新装回09可显式启用，随后才允许兼容降版。07 不认识08目录锁，仍是不兼容负例，不自动删除锁。

配置变化不包含业务域迁移、不可逆业务修改或整 profile 还原。应用业务记录、原生历史与凭据不被导出或倒灌。后续不可逆迁移必须另行说明影响并得到确认；当前没有这样的迁移实现。未知 schema、协议不兼容、产品安装失败应保持原状态并给出阻断诊断。

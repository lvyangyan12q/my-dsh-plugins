# Reading optional-platform cold-boot repair

Actual installed Browser RED: removing the workbench bundle caused reading Client factory materialization to fail with the official `client-modules: require(...) missed the module table` error. Reading also declared the platform service as a required entry dependency. The earlier absence artifact graph included only kaogong, so it missed this independent consumer.

The absence graph now includes both products. Reading imports platform types only at its factory boundary. Its entry has no required workbench service; the adapter registrations live in an optional Cordis child injection. The child resolves the real platform module only once the service exists, and its effects withdraw the renderer, source and template on service loss. Native logging explains the unavailable reading workbench entry and how to restore it; no reading records are initialized or changed by startup/recovery. Installed platform factory errors are not caught or hidden.

RED: the new official ClientModuleSystem test against the pre-fix built reading artifact failed at its top-level platform require, with no Node require fallback. GREEN: the same official resolver and exact rebuilt factory pass without any workbench bundle. Real Cordis entry activation is ACTIVE with the platform service absent. With the real built platform factory present, providing/withdrawing/reproviding the optional service registers 1/0/1 reading display sources while the reading entry stays ACTIVE.

Focused verification: 10/10 across optional-workbench, package-compatibility and reading-platform. The existing reading test context now implements its public service injection/provision contract. An initial run using the stale workbench Client artifact failed two existing UI tests; rebuilding just that Client from current source made those pass. Only reading and workbench Client artifacts were refreshed for this focused gate (an earlier wrong relative-path command rebuilt the small reading package before the edit; it did not modify product source or a live installation). No full release build, installed Browser boot, CSS visual assertion, model calls, Host restart, profile changes or live data writes were performed by this agent.

The independently installed `dsh-instance-proof` fixture still requires workbench at its own entry. It is not product code and is not covered by this product fix; the parent must independently make that fixture optional or retire it before an installed no-workbench boot can be accepted.

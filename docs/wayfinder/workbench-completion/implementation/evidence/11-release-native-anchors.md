# Release native anchors follow DSH_SOURCE (ticket 11)

The official release runner previously resolved product native dependencies from the plugin worktree. Switching DSH_SOURCE changed the CLI but could still install old native dependency links, so that result was insufficient evidence of the selected runtime's actual installation.

The public release dependency resolver now locates native @deepseek-ai package entries from the selected built workspace (its Node resolution, pnpm exposure, or exact package manifest name). Canonical package root and actual entry must remain strict children of canonical DSH_SOURCE. Missing builds or foreign native links fail explicitly with no old-core fallback. Ordinary third-party dependencies retain the worktree anchor, and product packages still come from exact archives. No compatibility policy or exemption was changed.

RED: a public isolated old/new package fixture linked the old worktree domain rather than the selected source domain. GREEN: four public tests cover the matching source manifest/built entry, foreign native junction rejection, unchanged third-party anchoring, and absent native build rejection. The release runner includes these tests in the existing gate and emits native-anchors.json plus nativeSource/nativeAnchors in its verdict for independent inspection.

Read-only dry-run of the physically isolated eba13b runtime found @deepseek-ai/schemastery resolving outside DSH_SOURCE; the new guard rejected it. That runtime dependency exposure must be corrected by its owner before claiming the new runtime installation gate. This slice did not build, install, start a Host, alter formal profiles, run the full release gate or close ticket 11. Native Win32 declared skips remain native limitations, not plugin exemptions.

Follow-up RED→GREEN: a root exposure resolving outside the selected source must be rejected, but the same source's normal pnpm public exposure can supply the exact contained package. A fifth public test covers this positive path; all five pass. Foreign root results are not used, and absence of a contained pnpm alternative still fails rather than falling back to old worktree packages. This supports normal built official workspaces without requiring additional root aliases.

After the runtime owner corrected its isolated public exposure, an actual read-only resolver dry-run found all seven required native anchors and their built entries strictly within the selected eba13b source (vendor schemastery and six named service packages). The seven ordinary third-party anchors were not redirected. This is dependency resolution evidence only, not a full archive install, Host lifecycle or completed ticket.

Full-gate follow-up: the clean 379-test run exposed two resolver failures under inherited NODE_PATH pointing at the new built runtime. Node lookup in a synthetic selected workspace inherited that external native package before discovering its own manifest; the positive local-manifest case and missing-build case therefore reported a foreign-source error. This was a resolver boundary defect, not a reason to delete NODE_PATH or weaken the foreign-package guard.

RED was reproduced with the full gate's unchanged DSH_SOURCE/NODE_PATH. Resolution now first verifies that the selected source actually exposes each public node_modules or pnpm package before using that lookup. Absent source exposure proceeds to exact local manifests; explicitly foreign source junctions still fail unless the same source has the reviewed contained pnpm alternative. A local manifest without self-reference exports cannot be shadowed by an inherited foreign entry: its own main remains authoritative. A sixth spawned-process public test fixes inherited NODE_PATH explicitly to an isolated foreign package, reproduces that additional RED, and verifies the selected manifest's built entry after the fix. No test expectation was weakened.

Six resolver tests pass under the full gate's unchanged inherited environment, Workbench source/type check passes, and the actual selected native runtime dry-run still yields seven contained native roots/entries with seven ordinary anchors unchanged. These targeted checks do not claim the clean full gate has been rerun or that release installation/Browser acceptance is complete. The previous 377/379 full-gate outcome remains a recorded failed attempt.

## Bounded implementation

The existing application registration `suspend` capability is now declared and exported as `WorkbenchAppRegistration` alongside its ordinary permanent disposer and metadata update. Only the source application's renderer lifetime integration changes; the platform registry's default permanent removal still retires windows.

KG captures supported native Client module manifest and source Loader entry metadata during registration. Cleanup suspends the registration when a still-installed, enabled source entry undergoes temporary app-slot withdrawal or code replacement. A confirmed source graph removal, disabled source entry, or unknown removed owner uses the permanent disposer. An older optional workbench without the capability also keeps its conservative permanent behavior. The source owner retains its latest registration across renderer withdrawal, so a later genuine disable still retires saved windows. That boundary first failed a new external regression, then passed after owner cleanup was preserved. Suspended registrations may subsequently retire their own saved windows; bounded ownership tokens prevent a stale disposer from retiring a newer registration. Live unavailable application definitions disappear in either case. No private core/storage/DOM access, native code mutation, business-table mutation, or automatic app reopening is introduced.

Native public `modules.manifest.plugins` is the package roster; its published update precedes entry graph reconciliation. Public `fiber.entry.disabled` represents explicit Loader disable including ancestor groups. This distinguishes source code replacement from application retirement instead of blanket suppression of all unregister operations.

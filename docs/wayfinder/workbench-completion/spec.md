## Problem Statement

用户需要一个能开发、管理和使用后续应用的工作台平台。已有应用画布、模块、数据连接、角色、标注和原生会话实现，但完整使用及交付仍未证明；实际侧栏停用有残留，真实模型执行及部分资料、视觉、迁移验收尚缺。构建、测试、原型和远程提交不能替代平台完成。

## Solution

按照平台稳定、应用搭建、AI 执行、应用接入、发布验收、正式交付六阶段推进。用户在布局画布各模块内配置内容与数据，选择角色，预览后显式启用；需要 AI 时准备可编辑上下文并通过 DSH 原生会话执行。阅读统计验证通用平台，考公验证复杂学习业务。

本规格补充并组织既有工作台规格、应用平台规格及后续画布调整，不替换其中任何要求。原有 123 条需求及其原文哈希保持；未验证、部分验证与明确失败项不得通过重命名、范围缩减或测试替代而计作完成。既有用户指示优先于历史文件中已过时的描述。

## User Stories

1. 作为用户，我希望原生工作区与会话菜单保留，以便继续使用 DSH。
2. 作为用户，我希望从原生菜单和兼容侧栏进入同一工作台，以便不产生重复应用状态。
3. 作为用户，我希望停用、热更新和卸载能正确清理入口和窗口，以便不留下失效内容。
4. 作为用户，我希望打开、关闭、最小化、恢复和调整窗口后保留状态，以便继续工作。
5. 作为用户，我希望浏览器刷新和 Host 重启能恢复持久状态，以便不用重复配置。
6. 作为应用作者，我希望先选择布局，再在各模块中配置，以便直观看到应用结构。
7. 作为应用作者，我希望添加、修改和切换页面，以便组织不同业务流程。
8. 作为应用作者，我希望配置网站、自定义内容、原生对话、动画和资源模块，以便组合不同体验。
9. 作为应用作者，我希望配置卡片、统计、列表、详情、筛选与地图展示，以便呈现应用数据。
10. 作为应用作者，我希望数据连接明确来源、应用归属及错误原因，以便可靠使用模块。
11. 作为应用作者，我希望筛选和选择在模块间正确联动，以便从概览进入详情。
12. 作为应用作者，我希望角色绑定管理入口建立的可复用 Agent 和 Skills，以便复用能力。
13. 作为应用作者，我希望应用私有角色和 Skills 保持应用归属，以便既有应用不被强行迁移。
14. 作为应用作者，我希望编辑、预览、保存草稿、显式启用和修改运行版本，以便控制发布。
15. 作为用户，我希望无效配置及缺失依赖能给出恢复路径，以便修正后继续使用。
16. 作为应用作者，我希望描述需求生成可编辑应用或模块草稿，以便降低开发成本。
17. 作为应用作者，我希望在画布任意位置标注要求并关联页面与模块，以便准确表达修改。
18. 作为用户，我希望提交前查看、编辑或移除任务上下文，以便控制发送内容。
19. 作为用户，我希望在应用中使用完整原生对话、轨迹和工具执行信息，以便跟踪结果。
20. 作为用户，我希望原生审批、提问、Stop 和流式执行可用，以便控制 AI 行为。
21. 作为用户，我希望执行期间关闭、重开、切换页面后保持正确会话与任务状态，以便继续任务。
22. 作为用户，我希望完成消息、历史会话和角色替换可追溯，以便恢复已有成果。
23. 作为用户，我希望 AI 生成结果能预览、修订和保存，以便完成从需求到应用的闭环。
24. 作为用户，我希望工作台自带应用搭建、模块生成、页面调整和数据展示 Skills，以便获得平台辅助。
25. 作为应用作者，我希望阅读统计走通搭建、数据和角色流程，以便证明平台通用性。
26. 作为考公学习者，我希望班主任、任课老师和辅导角色可持续使用，以便完成学习任务。
27. 作为考公学习者，我希望独立学习窗口容纳资料、教学、练习与总结，以便专注学习。
28. 作为考公学习者，我希望学习成果与统计正确落库并恢复，以便跟踪进度。
29. 作为考公学习者，我希望题目、选项、图片、表格和来源完整，以便可靠作答。
30. 作为用户，我希望旧数据、资料引用及会话身份在升级和回滚后保留，以便避免损失。
31. 作为用户，我希望按钮、下拉框和筛选框一致清晰，窄屏、键盘、中文输入法可用，以便日常操作。
32. 作为维护者，我希望实际发布包在不同依赖环境通过验收，以便确认部署可用。
33. 作为用户，我希望正式 3080 运行插件与远程版本一致并有启动及新增应用说明，以便持续使用平台。

## Implementation Decisions

1. 六阶段是执行顺序和门槛，不是新产品范围。可并行准备资料核验、视觉检查和模型条件；不得绕过所依赖的门槛。
2. 平台阶段负责入口、窗口、应用注册、状态恢复和清理；工作台保留唯一应用展示与状态所有者。
3. 画布配置优先模块内操作，集中表单仅作为高级配置；继续沿用已确认模板和布局，不重新引入未确认交互。
4. 应用由页面与模块组成；模板提供结构，模块选择内容及数据连接。展示不强制创建会话或调用模型。
5. 应用拥有业务数据；平台负责连接声明、共享展示和可观察依赖状态，不统一搬迁应用数据。
6. 可复用 Agent、Skills 来源于管理入口；应用私有能力保留。工作台包装四类平台辅助 Skills。
7. 角色会话按应用、实例、角色与学科身份稳定关联；页面和模块使用声明的角色，不把每个模块强制变成独立会话。
8. AI 生成和标注任务沿用任务预览及原生会话执行路径。生成结果先进入可编辑草稿，经预览后显式启用。
9. 完整 DSH 会话覆盖标题、对话、轨迹、输入、工具、审批、提问、模型设置和 Stop；不能复制或模拟来替代。
10. 可选侧栏清理仅经受支持的公共接口；具体稳定接缝由决策工单调查，不能靠私有 DOM 清理或核心业务硬编码。
11. 阅读统计和考公分别验证平台通用性及复杂接入。地图的真实数据由应用提供，不制造验收数据。
12. 题库资料修复以来源、题目身份、图片关联和完整性校验为依据；不猜写题目、改答案或暴露解析作答。
13. 旧考公目录保持观察期；迁移、升级与回滚需要验证真实记录及资料引用，不能删除旧路径来宣布完成。
14. 验收条件由实际安装包及用户可观察流程确定；模型条件不具备时保留相关未验收项，其他可独立工作继续。
15. 正式同步先完成隔离验证和保留检查，保护原生菜单、开源 Worktable、既有 Agent 改动、资料和用户数据。
16. 原需求、补充规格、决策地图和实施工单各有用途；决策地图只记录问题及答案，不代替执行验收清单。

## Testing Decisions

1. 用户于 2026-10-10 确认：以实际安装 DSH 的完整用户流程为最高验收边界，保留全部原要求。
2. 好测试断言外部行为、身份、数据和恢复结果；不以内部函数调用、固定快照或模拟结果代替业务完成。
3. 优先沿用现有应用生命周期、Host 持久化、原生角色绑定和实际安装浏览器接缝；无必要不新增测试专属接口。
4. 平台稳定验收覆盖打开、切换、窗口模式、刷新、重启、外部停用及热更新；核对菜单、草稿、会话和入口不受损。
5. 应用搭建验收创建并修改完整应用，配置页面、各类型模块、数据与角色，预览、保存、启用并重启后再次编辑。
6. AI 验收要求真实模型完成生成、画布标注和模块任务，验证上下文预览、执行、结果回填、修订及保存。
7. 原生会话验收要求实际完成消息、轨迹、工具、审批、提问、Stop、流式关闭重开、继续执行和历史恢复。
8. 同一使用链分别覆盖无可选侧栏、兼容侧栏及停用适配器环境；数据与应用状态一致，残留标签必须实际消失。
9. 阅读统计验收平台通用流程；考公覆盖角色、资料、独立学习窗口、练习评分、总结、确认完成与统计恢复。
10. 资料验收对照原来源检查题面、选项、图表和引用；纯哈希存在、文件可读不等于内容完整。
11. 浏览器和 Host 冷恢复同时检查持久业务记录、同一会话、运行版本及布局偏好，不隐式创建替代会话。
12. 视觉验收覆盖桌面与窄屏、按钮、下拉框、筛选、滚动、焦点和物理中文输入法；合成事件不替代物理输入验收。
13. 发布验收包括干净构建、全量回归、官方归档安装、精确字节、公开类型、原生模块解析、缺失及不兼容依赖、升级回滚和卸载重装。
14. 远程提交、正式部署、历史数据保留与全部需求验收分别记录。320 项历史绿灯只是当时回归结果，不是未来固定数量或总体完成证据。

## Out of Scope

本补充规划不新增通用市场、多人协作平台、替换 DSH 核心、自动升级第三方插件或强行迁移应用私有能力。原规格已经明确后移的跨应用真实数据授权与真实地图服务继续遵循原边界；其他原有要求不会因本节被移除。

## Further Notes

规格 ready-for-agent 表示终点和验收接缝获用户确认，不表示已实现或通过验收。当前缺陷和证据以完整需求清单、实际运行和决策工单为准。决策地图按 wayfinder 先澄清尚不确定的实施路径，再交给实现工单执行；不无限扩展功能，不把等待模型条件变成停止所有工作的理由。

路线：平台稳定 → 应用搭建闭环 → AI 执行闭环 → 阅读统计与考公接入 → 发布验收 → 正式交付。

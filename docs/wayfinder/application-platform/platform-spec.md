# 工作台应用平台规格

状态：ready-for-agent；产品决策与第一版验收边界已获用户确认。日期：2026-10-03。

## Problem Statement

用户需要让工作台成为后续多种应用开发、管理与使用的基础，而不是考公的专用容器。当前已有应用注册、独立 Agent/Skills 与持久角色会话，但新应用仍需重复编写布局、展示模块及上下文交接。卡片、统计、地图等展示与交互页面也应能够独立运行，不依赖 AI 会话。

## Solution

工作台提供应用中心、分步创建流程和应用管理。用户描述需求，AI 生成应用配方与必要专用组件，进入可编辑草稿；预览确认后显式启用。页面选择布局并组合公共模块；复杂业务可以扩展专用组件。

应用拥有业务数据。页面模块共享筛选与选中项，跨应用通过明确数据连接读取。角色引用独立 Agent/Skills，原生会话按应用实例与角色保留。模块任务动作先准备任务和上下文，用户可编辑、移除并发送；普通展示、筛选和选择不调用模型。

## User Stories

1. 作为用户，我希望在应用中心查看多种应用，以便工作台服务于不同业务。
2. 作为用户，我希望保留 DSH 原生菜单，以便继续使用原来的工作区与会话功能。
3. 作为用户，我希望描述需求生成应用草稿，以便降低新增应用成本。
4. 作为用户，我希望编辑应用名称与说明，以便明确应用用途。
5. 作为用户，我希望选择页面布局，以便匹配看板、阅读与详情场景。
6. 作为用户，我希望组合统计卡片和列表等公共模块，以便复用已有功能。
7. 作为开发者，我希望接入专用组件，以便表达通用模块无法承载的业务。
8. 作为用户，我希望预览草稿，以便验证页面和数据联动。
9. 作为用户，我希望显式启用应用，以便生成过程不直接修改运行版本。
10. 作为用户，我希望查看应用配置和依赖，以便管理后续应用。
11. 作为用户，我希望停用应用后保留数据与会话，以便恢复使用。
12. 作为用户，我希望停用应用不能被误打开，以便状态与行为一致。
13. 作为用户，我希望从平台打开考公应用，以便复用现有学习数据。
14. 作为用户，我希望没有 AI 的展示应用也能运行，以便浏览统计和信息。
15. 作为用户，我希望统计卡片随筛选更新，以便看到正确范围的数据。
16. 作为用户，我希望列表、地图和详情同步选中项，以便理解当前对象。
17. 作为用户，我希望看到加载、空数据和失败状态，以便区分数据状态。
18. 作为用户，我希望数据属于相应应用，以便避免应用之间互相覆盖。
19. 作为用户，我希望明确配置跨应用数据连接，以便知道数据从哪里来。
20. 作为用户，我希望给应用角色引用 Agent 和 Skills，以便复用独立能力库。
21. 作为用户，我希望在多个页面继续同一角色会话，以便历史不会碎片化。
22. 作为用户，我希望不同应用实例的会话独立，以便上下文不混淆。
23. 作为用户，我希望模块动作选择合适角色，以便把任务交给正确职责。
24. 作为用户，我希望发送前查看、编辑或移除上下文，以便掌握实际交接内容。
25. 作为用户，我希望选择与筛选不自动调用 AI，以便使用展示页面不产生隐式请求。
26. 作为用户，我希望更换 Agent 后保留旧会话，以便历史可追溯。
27. 作为用户，我希望刷新后恢复已启用应用和角色关联，以便持续使用。
28. 作为用户，我希望配方缺少模块或能力时显示原因，以便修复而不是得到空白页面。

## Implementation Decisions

- 工作台为平台型插件；考公与后续业务应用均为接入应用。业务规则、业务数据与专用组件不进入平台核心。
- A 应用中心作为首页，B 分步创建流程用于开发，C 目录与配置用于管理；原型只提供交互依据，正式实现需重写。
- 应用配方声明稳定应用身份、版本、页面、布局、模块、数据连接、共享交互状态及角色引用。配方不内嵌凭据、对话历史或业务记录。
- 应用定义与应用实例区分；实例具有独立业务状态和角色关联。模块身份、页面身份及角色身份应稳定，显示名称可以修改。
- 页面布局与模块内容独立。公共展示、交互与角色对话模块共享组件入口；专用组件通过受支持的注册接口扩展。
- 业务数据由应用拥有，数据连接具有明确来源和可用状态。默认不直接读取其他应用私有数据；跨应用读取必须通过声明的连接。
- 页面共享筛选、选中项等交互状态，模块通过声明关系联动。更新这些状态不产生模型请求。
- 会话关联以应用实例与角色为边界。同一角色可跨页面复用；角色引用同一个 Agent 不意味着跨应用共用会话。
- 模块动作声明任务目标与必要上下文。交接先进入待发送状态，允许编辑或移除；显式发送后才调用原生角色会话。清楚显示目标角色和上下文来源。
- Agent/Skills 仍独立管理；工作台管理引用及使用关系，不复制能力库。缺少、停用或不可调用的能力使相应任务动作不可用并说明原因。
- 草稿、预览与已启用版本区分。AI 生成结果进入草稿；生成或预览不改变已启用应用。启用前校验结构、模块及能力引用，失败不替换运行版本。
- 停用不删除业务数据、配方或历史会话。启用停用只改变应用可用性；删除与永久清理不在本期范围。
- 沿用现有应用注册、原生角色绑定、原生会话和持久化能力；保持 DSH 原生导航可用。考公资料路径与学习数据保持可恢复。
- 首版公共模块为统计卡片、数据列表、详情与筛选，以及现有角色对话区。地图保留专用组件扩展接口，本期不要求真实地图服务。

## Testing Decisions

- 验证外部行为，避免测试内部对象结构与组件排列细节。优先沿用已有应用注册生命周期、真实 Host 持久化、构建后的 Client 交互及原生会话运行时边界。
- 主要验收链：需求生成草稿 → 配置模块与连接 → 预览联动 → 显式启用 → 从应用中心打开 → 停用与恢复。生成与预览期间运行应用保持原状态。
- 展示链：同一筛选更新统计与列表；选中列表对象更新详情；示意地图联动仅为原型证据，真实地图不纳入首版验收；纯展示过程无模型请求。
- AI 链：模块动作准备指定角色和上下文 → 用户修改或移除 → 显式发送 → 原生会话保留。跨页面复用，跨实例隔离，角色更换保留旧历史。
- 恢复链：应用定义、启用状态和角色关联在刷新/重启后恢复；停用不丢业务数据。无效引用显式失败，不默认为其他角色或偷偷创建新会话。
- 平台复用以考公和一个简单展示应用验收（采用阅读统计作为实现示例：自有数据、统计卡片、列表、筛选与详情，不依赖 AI）：公共模块被两个应用使用，平台核心不包含考公或第二应用的业务条件判断。
- 原生回归：菜单及会话导航可进入；返回应用后保留状态；现有考公记录和历史资料仍可访问。
- 原型是内存演示，不作为真实生成、持久化、地图服务或模型调用的通过证据。实际实现需浏览器验收和原生运行时验证。
- 用户已确认以上测试边界：以考公和简单展示应用验证平台闭环；保留地图扩展接口，真实地图后移。

## Out of Scope

- 本规格整理阶段的生产实现与部署。
- 强制所有模块无代码化、自由拖拽平台、任意代码执行平台。
- 删除原有考公资料或调整 DSH 原生功能。
- 将 Agent/Skills 并入工作台专属管理。
- 地图供应商选择、导航与复杂地理分析，以及尚未确定的外部数据凭据管理。
- 自动覆盖运行版本、自动发送模块上下文、永久删除应用数据。

## Further Notes

原型与用户确认记录保存在决策地图中，原型归档于独立分支。现有平台注册与会话功能是实现基础，但不代表已具备应用配方生成、模块注册及版本启用流程。

首版第二应用只验证展示和模块复用，无须真实地图或外部授权服务。地图扩展、跨应用真实数据源授权、业务数据结构迁移与自动升级为后续范围；本期仅支持当前配方版本，遇到不支持的版本或缺失依赖明确拒绝启用并保留现有运行版本，不做隐式迁移。阅读统计是验证应用的实现示例，可替换为同等范围的独立展示应用。

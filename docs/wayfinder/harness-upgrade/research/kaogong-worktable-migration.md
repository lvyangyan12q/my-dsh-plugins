## 结论

考公需要的是应用侧重接入和业务状态分区，不能只把 `personalWorkbench` 名称替换成 `worktable`。现状是六个固定领域、一个默认学习上下文和旧平台拥有的角色绑定。SDK 已提供实例/视图、由所属应用执行的资源读写、实例授权、私有能力和待发送任务，但不会替考公拆分旧记录、复用旧绑定，或提供旧课堂内嵌原生对话工厂。[旧 Host](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/index.ts#L286)、[旧 Client](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/client.tsx#L163)、[SDK 合同](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/sdk.d.ts#L14)

建议将旧学习历史整体接管到一个明确的、初始未归属项目的历史实例；题库和经确认的资料由考公所有者保留一份，再向选定学习实例显式只读授权。旧知识库含“笔记”，不能整库视为公共讲义。保留旧 ID、原题快照、提交顺序、课堂与角色关联、原生会话和 cwd，不按项目复制或重新评分。[知识类型](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/types.ts#L83)、[记录结构](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/schemas.ts#L105)、[课堂结构](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/lesson-schema.ts#L20)

至少需要补充 Worktable 的公开旧绑定接管合同；如果完整保留课堂左右并列、持续挂载的原生对话交互，还需要评估公开嵌入接缝。只采用当前 SDK 的“打开原生对话”会改变现有课堂交互，不能作为等价完成。[旧课堂](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/kaogong/src/classroom.tsx#L101)、[当前应用视图](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/client/applicationViews.tsx#L33)、[角色导航](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/client/rolePanel.tsx#L30)

## 数据现状：应用全局与 default 的准确含义

这里的“全局”指考公一份固定命名领域、同部署下业务代码共同访问；不代表公开给外部用户，也不代表题库已获得跨实例授权。`default` 是考公/旧平台自己写死的实例键，并非原生 storageDomain 提供的 scope 参数。rc.3 `open(spec)` 只收领域声明、按 `spec.name` 路由后端并拒绝重复打开；领域声明包含表与可选 global 单例，没有 instanceId 分区机制。[原生 open](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/storage/storage-domain/src/index.ts#L103)、[领域声明](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/storage/storage-domain/src/spec.ts#L35)

## 候选接管方案（建议，尚未批准）

**方案 A：一个历史学习实例 + 专用资料库实例，建议作为首个迁移规格。**

- 由正常 SDK 创建一个未归属项目的学习实例；考公另存稳定 legacy-default → 新 instanceId 映射及 receipt。旧 notebook/progress/practice/lessons（含旧笔记）整体归此实例；不拆成绩、不复制进每个项目。可先用应用侧兼容读取层保留旧领域，待批准再分区；领域名保持单一 writer。后续新实例从空学习状态开始。
- 考公建立专用资料库实例/视图，仍只持有一份题库与已确认资料；学习实例逐个授权只读引用。可将资料库声明为独立资料应用，或在考公自己的实例元数据标识 library 类型；平台无需新增全局 scope。授权之外的 owned 读取必须由 owner 拒绝，不能因同 app 自动把学习实例当库所有者。
- 普通“笔记”、课堂摘要/讲评、用户新录入内容留历史实例私有；共享清单由应用检查器生成脱敏 ID/类型/来源/数量影响，用户确认后才扩展。未知归属先保留，不根据标题或目录猜测。题库维护与资料同步需显式 owner 写操作；不把只读分享解释成不允许资料 owner 正常维护。
- 接管先预览旧键→新角色键、原 Session/preset/cwd、phase 和 prior IDs 的映射，随后通过补充的公开平台接口应用。ready 只 attach 已验证的同一原生 Session；intent 及缺失/归档/不可访问状态保持原状态与恢复提示，不以 ensure 创建替代。历史 Session 不复制到多个新实例或多个角色。
- 应用迁移日志将业务切换与平台角色 receipt 分阶段记录，重试必须幂等；原生会话文件继续由原生持有，禁止复制历史消息到应用表。旧部署冻结包与业务恢复是两个方案，不能通过回滚旧整库丢掉迁移后新增学习记录。

此方案沿用既有实例、资源和 ADR 语义，但仍需要考公业务实现、平台公开绑定接管合同以及联合恢复设计；并非 SDK 当前已支持一键迁移。旧 previousSessionIds 若一次性导入，必须校验全局唯一所有权并保留错误记录；不能把内部 attach 反复执行当完整历史迁移。[新角色唯一性](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/framework/state-schema.mjs#L23)、[角色替换/attach](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/framework/roles.mjs#L35)、[迁移恢复合同](https://github.com/lvyangyan12q/my-dsh-plugins/blob/8b6faddefccbc339ddc9f09f706c880f451f89da/plugins/worktable/01_content/src/sdk.d.ts#L27)

**方案 B：先兼容旧 default，延后多实例迁移。** 新 SDK 只登记一个可恢复旧学习数据的实例，拒绝新增考公学习实例或显示“尚未迁移”的独立状态；题库/资料/历史学习仍由原考公 writer 持有。优点是先减少数据结构变化；代价是尚未满足独立学习实例和跨实例显式共享，不能作为完整交付。若角色仍依赖旧平台，则也不算迁移到派生 SDK 已完成。此方案只能经明确范围决策成为阶段交付，不能让 UI 创建多个其实共用旧全局数据的假实例。

## 最少待用户决策

1. 是否接受方案 A 的归属：旧 default 的学习历史整体由一个初始未归属项目的历史实例接管；新实例学习状态空白；题库/明确选定源资料通过专用资料库实例显式只读分享，旧课堂笔记默认私有。此处确认归属原则，不授权执行正式迁移；具体条目和绑定影响留待只读预览确认。
2. 首次考公交付是否必须保持课堂内嵌原生对话的完整交互，还是允许暂用 SDK 的“打开原生对话”。前者需扩展/验证嵌入接缝，后者是可见交互变化，必须明确接受，不能由研究者自行降级。

角色 ID 编码、分区存储方式、迁移 receipt 字段和 lease 实现可由后续技术规格确定，无需用户逐项选择。缺失旧会话等真实异常的恢复选择只在预览发现该异常后提出，本轮没有读取正式记录，不虚构需要处理的冲突。

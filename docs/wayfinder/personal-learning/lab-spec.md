# 知间 · 学习实验台

日期：2026-11-07。本规格接续[个人学习插件规格](spec.md)，不覆盖其历史验收；设计依据是 B 原型
`b-lab.html`（已选定）。本地任务见 [issues/](issues/)。

## Problem Statement

个人学习插件已经能创建学习空间、绑定原生教学会话、用 `/teach` 生成课程并保留学习证据，但它当前只能
声明运行在 DSH `0.2.2-alpha.2`：宿主已到 `0.2.2-rc.1`，插件装上却不会启用。

课程页本身也没有围绕教学组织。打开一个空间后，用户同时面对课程列表、刷新按钮、下一步建议、
教学请求编辑（待发送请求下拉、资料标题/链接/摘录、准备/保存/发送）、会话入口和恢复面板。
抽象概念仍然主要靠文字和一张整页 iframe 解释，学习者没有“先猜、再操作、才看到答案”的过程，
看得懂与真的会之间的差距没有被检验。

## Solution

把课程页改成一台**实验台**：左边是这一课的可交互实验画布，右边是老师工作台，固定三段——
先猜、解释、复述。预测之前，读数隐藏、控件锁定、解释只显示占位；预测之后才解锁数字和针对性解释；
复述用关键词检查，通过才允许把这一节记为已学。

`/teach` 生成的课程通过一份**受支持课程协议**声明自己的实验参数、预测题、读数与复述检查项；
有协议的课进入实验台，没有协议的旧课降级为只读阅读，并明确说明原因，不假装支持交互。

同时把宿主兼容升到 `0.2.2-rc.1`，让插件能在当前 DSH 上真实安装、启用、跑通完整一课。

配置不进主界面：教学请求、会话、资料、恢复收进课程页的「⋯」抽屉；主界面只保留这一课和下一步。

## User Stories

1. 作为学习者，我希望在当前 DSH 版本上正常安装并启用学习插件，以便不用为了一门课降级宿主。
2. 作为学习者，我希望打开学习空间后直接看到“这一课要动手做什么”，以便不用先理解一堆配置。
3. 作为学习者，我希望实验画布占据课程页的主要空间，以便抽象关系可以被直接看到。
4. 作为学习者，我希望先回答一个预测问题，再看到数字和解释，以便检验自己的直觉而不是被直接告知答案。
5. 作为学习者，我希望预测前读数是未知的，以便我不会从界面上偷看结果。
6. 作为学习者，我希望预测前控件不可操作，以便“先猜”不是一句可跳过的提示。
7. 作为学习者，我希望预测后立刻得到针对我选项的反馈，以便知道我是怎么想错的。
8. 作为学习者，我希望拖动参数时画布、数字和解释同步变化，以便建立因果关系。
9. 作为学习者，我希望读到与自己操作相关的解释，而不是一段通用定义，以便解释能对上我看到的画面。
10. 作为学习者，我希望在参数到达边界时得到明确说明，例如分母为 0 时条件概率未定义而不是 0%。
11. 作为学习者，我希望用一句话复述这一节的机制，以便确认自己不是只会拖滑块。
12. 作为学习者，我希望复述反馈指出我漏了哪个要点，以便知道补哪一句。
13. 作为学习者，我希望复述通过后才出现“记下这一节”，以便完成状态不被一次答对冒充。
14. 作为学习者，我希望单次通过不被标成长期掌握，以便复习建议仍然可信。
15. 作为学习者，我希望每一节的预测、参数轨迹和复述结果被记录下来，以便以后回看当时的理解证据。
16. 作为学习者，我希望这些证据关联到具体课程版本，以便课程更新后旧证据仍然可解释。
17. 作为学习者，我希望重新打开这一节时恢复我离开时的参数，以便继续而不是重来。
18. 作为学习者，我希望刷新或重启宿主后仍能回到同一节和同一组参数，以便学习不中断。
19. 作为学习者，我希望切换学习空间不会串掉另一个空间的课程与参数，以便多个主题互不影响。
20. 作为学习者，我希望没有交互协议的旧课仍能正常阅读，以便升级不破坏已有内容。
21. 作为学习者，我希望旧课明确标注“这一课不支持实验台”，以便知道为什么没有控件。
22. 作为学习者，我希望在课程页随时向老师追问，并带上当前课程、参数和我的疑问，以便少解释一遍背景。
23. 作为学习者，我希望追问发到原生教学会话，而不是另一个聊天框，以便停止、审批和历史都在一处。
24. 作为学习者，我希望教学请求、资料和恢复都不常驻主界面，以便注意力留在这一课上。
25. 作为学习者，我希望用一个「⋯」入口找到低频操作，以便需要时能找到、不需要时不打扰。
26. 作为学习者，我希望窄屏下实验画布在上、工作台在下，以便不横向滚动也能完成一轮。
27. 作为学习者，我希望键盘能完成预测、调参、复述和继续，以便不依赖鼠标。
28. 作为学习者，我希望课程生成失败或取消时保留原来的课，以便不因为一次失败丢掉已学内容。
29. 作为学习者，我希望老师生成的新课如果不符合协议，会被明确拒绝并说明缺什么，以便不会出现半可用的实验台。
30. 作为学习者，我希望课程页只有一个主行动，以便任何时候都知道下一步点哪里。

## Implementation Decisions

### 宿主兼容

- 目标宿主改为 DSH `0.2.2-rc.1`，`engines.dsh` 与两个 peer（storage-domain、tools）同步到该版本。
- 不保留 alpha.2 的双版本兼容；历史安装包与验收记录保留为证据，不回写为通过。
- 发布仍走现有官方离线安装流程与 installed-gate；版本范围变化必须重新跑门禁，不复用旧哈希。

### 课程页结构（实验台）

- 课程页由三块组成：画布、工作台（先猜 / 解释 / 复述）、底部主行动。
- 配置类内容（教学请求编辑、待发送请求、资料、会话、恢复）移出主界面，进入「⋯」抽屉，按组收纳。
- 工作台三段有明确的状态依赖：未预测时第二、三段不可用；复述未通过时主行动不出现。
- 侧栏老师追问复用原生会话，消息携带当前课程 id、课程版本与已捕获参数。

### 实验台状态机

来自 B 原型，作为实现基准：

```text
predict(未答) --选项--> predicted(对/错 + 反馈)
                    |--> controls 解锁, readouts 显示, explain 展开
predicted --调整参数--> 读数/解释实时更新（不改 predicted）
predicted --复述通过--> passed --> 主行动出现
```

- 任何时刻只有一个主按钮；`passed` 之前它不存在，而不是禁用。
- 参数变化不撤销预测，也不回退到未答状态。

### 受支持课程协议 v1

- 课程可声明 `interaction`：参数列表（id、范围、初值、步长）、读数（id、表达式或映射）、画布渲染所需的参数绑定。
- 课程可声明 `prediction`：问题、选项、正确项、每个错误选项的反馈、预测前是否隐藏读数。
- 课程可声明 `restate`：提示语、检查项（关键词或断言）、通过条件。
- 协议由宿主校验：参数越界、读数引用不存在的参数、预测正确项不 ∈ 选项、复述检查为空，都拒绝该课并给出可操作原因。
- 无协议的课不进入实验台，按只读 iframe 呈现，并在页面上说明“这一课不支持实验台”。
- 协议是课程产物的一部分，随课程版本一起保存；不把 React 组件或函数写入持久存储。

### 判定与证据

- 预测对错由宿主判定并记录，不依赖课程脚本自报。
- 复述检查由宿主按协议执行，记录命中的检查项与缺失项；通过才写入“本节完成”证据。
- 证据记录课程 id、版本、参数快照、预测结果、复述结果与时间；不据此推断长期掌握。
- 参数快照只接受当前实例、当前课程的合法参数；越界值拒绝而不是截断。

### 配置与旧课

- 主界面不出现下拉框、刷新、准备、保存、发送等配置动作；它们只在抽屉内。
- 旧课缺协议时保留历史记录与打开能力，不迁移、不改写原题内容。
- 课程更新产生新版本时，旧证据继续指向旧版本。

## Testing Decisions

- 最高测试边界仍是**真实安装的 DSH 用户流程**：安装 → 启用 → 打开空间 → 选课 → 预测 → 调参 →
  复述 → 记下 → 刷新/重启恢复。新增的自动化只补这条路径难以覆盖的协议与状态判定。
- 好的测试断言用户可见行为与持久结果：未预测时读数不可见、控件不可用；预测后数字正确；
  B 为 0 时显示“未定义”；复述缺项时指出缺哪项；无协议课显示只读说明；参数与位置重启后恢复。
  不断言组件内部状态、私有函数或 DOM 类名。
- 模块测试范围：课程协议校验（纯逻辑）、实验台状态机（纯逻辑）、参数快照与证据写入（HTTP）、
  旧课降级路径。沿用现有 `tests/*.test.mjs` 的组织方式，不为每个组件新建测试文件。
- 浏览器验收：桌面 1440 与窄屏 390 各跑一轮；键盘完成预测与复述；截图记录。
- 安装门禁：在 `0.2.2-rc.1` 官方构建上重新执行 installed-gate，记录新哈希；旧 alpha.2 回执只作历史。
- 真实模型至少生成一课并完成一轮，确认 `/teach` 能产出带协议的课程；替身样本只用于自动化。

## Out of Scope

- 重做知识地图、角色体系或多角色协作。
- 提升生成课程的教学质量本身，或对学习效果作量化保证。
- 其他学科、多设备同步、公开部署。
- 迁移或改写已有考公数据。
- 把 alpha.2 的旧验收提升为新宿主上的通过。

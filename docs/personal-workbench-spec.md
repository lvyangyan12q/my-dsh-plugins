# 个人工作台插件与考公应用接入规格

状态：用户已确认完整使用流程的测试边界，并选择本地任务文件；开发分支为 codex/personal-workbench。

日期：2026-10-01。

## Problem Statement

用户需要在 DSH 中统一管理应用、Agent 和 Skill，并让后续应用以插件方式接入。当前考公插件以独立面板呈现，老师讲解仍需要复制提示词后新建对话，无法在课堂内持续与固定角色交流。讲义、题目、学习记录和角色会话之间缺少稳定关联。

用户已经安装 Better Sidebar，希望工作台嵌入 DSH 侧边栏，并能够与 Better Sidebar 共存或从其界面打开，不能因为缺少任意一个第三方插件而导致考公不可用。

## Solution

开发独立个人工作台插件，使用官方 DSH 插件安装、客户端注册、布局、会话和持久化能力。工作台统一管理应用入口、应用实例、窗口和角色会话关联；考公作为第一个接入应用，继续拥有题库、讲义、练习、错题和学习计划。

主入口注册到 DSH 侧边栏。Better Sidebar 作为可选展示入口，使用已安装版本公开的 Tab 注册机制展示同一工作台，不创建第二份数据和独立窗口状态。

考公窗口提供课堂、模块练习、错题复习、讲义资料和学习计划。课堂并排展示图文材料和角色对话，角色包括班主任、任课老师和辅导员。角色使用持久 DSH 会话，而不是临时子代理或复制提示词的跳转按钮。

分阶段交付同一规格：先验证一个老师的真实嵌入会话，再实现工作台与考公接入，最后扩展多角色和 Agent、Skill 的关联管理。未完成阶段不标记为已支持。

## User Stories

1. 作为用户，我希望从 DSH 侧边栏打开工作台，以便集中访问我的应用。
2. 作为用户，我希望在没有 Better Sidebar 时仍能使用工作台，以便不被第三方插件依赖阻断。
3. 作为用户，我希望安装 Better Sidebar 后能从其 Tab 打开工作台，以便沿用已有侧边栏布局。
4. 作为用户，我希望两个入口展示相同应用和状态，以便不会出现两份互相矛盾的工作台。
5. 作为用户，我希望按应用、Agent、Skill 分类查看内容，以便区分业务应用、角色和方法。
6. 作为用户，我希望看到条目的所属应用、来源及可用状态，以便知道哪些是自建、社区或应用内置内容。
7. 作为用户，我希望搜索、收藏、排序和隐藏应用，以便快速找到常用入口。
8. 作为用户，我希望点击考公打开应用窗口，以便在一个连续界面内学习和练习。
9. 作为用户，我希望重复打开同一应用实例时聚焦现有窗口，以便避免重复创建窗口和会话。
10. 作为用户，我希望最大化、最小化、恢复和关闭窗口，以便按当前任务安排空间。
11. 作为用户，我希望窗口在小屏幕上能切换为单栏且内容不重叠，以便正常阅读材料和输入消息。
12. 作为用户，我希望窗口布局在刷新后恢复，以便不必重新调整宽度和 Tab。
13. 作为用户，我希望关闭窗口后学习数据和对话保留，以便下次继续。
14. 作为用户，我希望切换 Tab 或收起窗口不会自动停止 Agent，以便后台工作不中断。
15. 作为用户，我希望看见角色运行中、等待授权、失败和新消息状态，以便及时处理。
16. 作为学习者，我希望从老师 Tab 直接发送问题并收到流式回答，以便不用复制提示词再切换主会话。
17. 作为学习者，我希望班主任、任课老师和辅导员分别保留历史，以便不同职责的讨论不会混在一起。
18. 作为学习者，我希望任课老师按科目绑定会话，以便资料分析和判断推理的课堂互不混淆。
19. 作为学习者，我希望老师加载真实可用的教学 Skill，并明确提示缺失依赖，以便不会假装技能已加载。
20. 作为学习者，我希望左侧材料保留图片、表格和来源，以便对照原始题目学习。
21. 作为学习者，我希望老师能引用当前材料和课堂目标，以便讲解与正在学习的内容一致。
22. 作为学习者，我希望按模块开始十题练习并继续下一轮，以便循环巩固知识点。
23. 作为学习者，我希望提交前不显示答案，提交后显示真实成绩和解析，以便获得可信的练习结果。
24. 作为学习者，我希望将本轮真实错题交给辅导员讲评，以便得到针对性总结和补练建议。
25. 作为学习者，我希望课后任务、完成状态和课堂总结持久保存，以便跟踪学习进度。
26. 作为学习者，我希望其他角色读取必要的计划和总结而非全部聊天记录，以便协作时保持职责清晰。
27. 作为用户，我希望查看角色使用的模型、Skill 和工具权限，以便了解角色能做什么。
28. 作为用户，我希望为角色分配已有 Skill 并检查可用性，以便形成可复用的角色配置。
29. 作为用户，我希望应用内置角色默认归属应用展示，以便全局 Agent 列表不会被重复入口挤满。
30. 作为用户，我希望现有考公学习记录、题库和 MinerU 资料保留，以便升级后继续学习。
31. 作为用户，我希望缺失、归档或不可访问的角色会话有明确恢复选项，以便不会静默新建并丢失上下文。
32. 作为用户，我希望卸载工作台后仍能独立打开考公，以便应用不会依赖工作台才能使用。
33. 作为应用开发者，我希望声明应用入口、页面、默认布局和角色即可接入，以便无需复制窗口管理代码。
34. 作为应用开发者，我希望插件停用或热更新后注册能正确清理，以便没有重复入口和失效窗口。
35. 作为用户，我希望依赖不兼容时只看到清晰的不可用状态，以便不会因可选扩展导致整个工作台白屏。
36. 作为用户，我希望从管理入口进入官方插件和配置功能，以便不需要维护另一套安装器或密钥管理。

## Implementation Decisions

- 工作台与考公为两个独立 DSH 插件包，放在现有多插件仓库中发布，不修改 DSH 核心来硬编码业务。安装包需包含可加载的宿主和客户端产物，并声明实际消费的宿主版本兼容范围。
- 用户指定界面参考 awesome-design-md 中的 Claude 设计。采用克制的暖白背景、深色文字和珊瑚色重点操作，适配工作台信息密度；不复制营销页布局、品牌标志或未授权字体，不更改 DSH 与 Better Sidebar 的全局样式。
- 应用、Agent 和 Skill 是用户管理对象；插件包是交付单元。一个插件包可以提供多种管理对象，不把“自建”作为功能类别。
- 使用小范围应用注册接口，承载唯一标识、版本、名称、图标、页面入口、默认布局、角色与依赖声明。注册返回清理操作；重复标识明确拒绝；注册与卸载不执行模型调用。
- 注册表描述当前安装插件提供的能力，不把客户端模块、函数或 React 内容序列化到持久存储。持久状态保存稳定标识，启动后按当前注册恢复引用。
- 应用定义与应用实例区分。第一版为现有考公提供默认实例，已有学习数据继续归属于该实例；不同时承诺多套独立题库和计划。
- 工作台主入口使用官方侧边栏扩展点。窗口使用官方 Overlay、浮动和分屏布局能力；不依赖 DOM 类名匹配、移动官方聊天 DOM 或修改其边距来挤出空间。
- Better Sidebar 适配为可选模块，按公开的注册、打开和清理接口接入。没有该插件时不加载其专属运行时依赖；存在兼容版本时贡献工作台 Tab；未知或不兼容版本提示原因并保留主入口。
- Better Sidebar 内展示入口或适合窄栏的管理视图；点击应用进入统一应用窗口。适配层不注册第二套考公业务接口、不复制角色会话、不截取全部文件链接。
- 同一应用实例默认一个窗口，重复打开仅聚焦或恢复。收起窗口、切换内容或取消 UI 订阅不等于停止、归档或删除会话。
- 窗口位置和尺寸限制在可视区域内；小屏幕使用单栏页面切换。支持键盘操作、焦点管理及关闭后焦点返回；输入和图文内容不得被窗口遮挡。
- 工作台通过 DSH 会话能力管理角色会话，不实现第二个 Agent 执行引擎。持久关联按应用实例、角色及可选科目索引到会话；创建使用幂等控制避免并发重复。
- 第一实现门槛为官方会话的完整嵌入验证：历史、输入、流式消息、工具结果、授权及提问交互、运行状态和停止均绑定正确角色。若公开接口无法满足，不以只能跳转主聊天的界面冒充完成，需要在开发记录中明确阻塞和调整方案。
- 运行状态来自真实 DSH 会话订阅；可见视图按需保留会话引用。卸载视图释放订阅不应取消持久会话中的工作；重新打开加载既有历史和状态。
- Agent 使用官方角色预设和配置能力。Skill 的发现、加载、工具权限及模型配置复用 DSH；工作台只管理引用和关联，不向模型声称未加载的 Skill 已可用。
- 角色初始教学规则来自实际安装内容，不依赖硬编码的开发者磁盘路径。已有旧角色配置需迁移到当前宿主机制，不复活已删除的运行时插件。
- 将考公内容模块从独立全屏面板中分离，同一视图能被工作台和独立入口使用。工作台存在时优先提供注册入口，缺席时保留官方侧边栏入口，不通过多次挂载生成重复状态。
- 保留考公既有题库筛选、循环练习、成绩、错题、知识库和计划逻辑。复用安全图文渲染及本地资源路由，不重新解析全部 PDF，不改变原题 ID、选项或答案。
- 课堂关联目标、讲义引用、练习结果、课后任务和总结。真实成绩由考公逻辑计算和持久保存；角色不能通过文字回复伪造完成状态。练习提交需要防重复，老师讲评不重复入账。
- 工作台保存窗口和角色会话关联，考公拥有业务数据，DSH 拥有会话历史。重要关联使用宿主持久存储并带版本；浏览器只缓存展示偏好，不作为角色关联的唯一来源。
- 旧数据采用最小必要的加法迁移，先提供可恢复备份及迁移校验，不删除原资料。新实例记录与旧单实例业务数据的对应关系明确保存。
- 会话失效、归档或不可访问时明确提示，由用户选择恢复或新建；不得静默换一个会话。缺失模块和图片具有独立错误状态，不能引发整个工作台崩溃。
- Token 和其他凭据继续使用宿主现有凭据机制，不进入应用注册信息、客户端持久状态、日志、导出规格或 Git 仓库。
- 第一版提供已有应用、Agent 和 Skill 的查看与关联管理，复杂角色编辑器和全量 Skill 编辑器另行迭代。界面只展示实际发现的可用对象，不使用演示列表充当真实能力。

## Testing Decisions

- 主要测试边界是用户可见的工作台接入流程：从侧边栏打开工作台，进入考公，使用材料、练习和角色会话，再关闭、刷新及恢复。用户已确认按完整使用流程验收，并覆盖安装与未安装 Better Sidebar 两种情况。
- 好的测试断言结果和可见行为，不断言组件内部状态、私有函数或具体 DOM 类名。底层 DSH 服务可以使用受控的真实接口替身，但不能用假聊天替代关键真实宿主集成验证。
- 完整流程分别覆盖没有 Better Sidebar、启用兼容 Better Sidebar 和停用适配插件的环境；核心工作台和考公数据保持一致。兼容目标以实际安装的 DSH 0.2.0-rc.2 与 Better Sidebar 0.24.1 为首个验证组合，不扩展宣称所有版本可用。
- 一个老师会话真实嵌入的集成测试作为第一道门槛，覆盖发送、流式输出、授权、停止、关闭重开、刷新和宿主重启续聊。会话操作不得误作用于 DSH 主聊天或其他角色。
- 通过插件生命周期验证注册、重复打开、禁用、卸载和热更新，确认没有重复入口、残留订阅和隐式模型调用。
- 验证角色隔离、按科目关联、并发创建去重及会话缺失恢复。切换 Tab 不丢输入草稿；关闭窗口不会取消正在运行的任务。
- 使用考公现有纯逻辑测试作为题库选择、练习、错题、知识搜索和计划的回归基础；保留已有 MinerU 与材料修复测试，不重写无关业务测试。
- 使用现有无密钥宿主测试夹具扩展课堂和讲评记录行为，验证真实作答、课后任务以及总结关联，不依赖外部模型价格或概率输出。
- 选择含表格、跨页材料和图片的本地题目及讲义作为图文验收样本，断言资源可访问、图表实际渲染、来源正确、提交前不泄露答案。
- 持久化测试覆盖旧考公默认实例接入、迁移重跑、关联恢复和损坏记录提示；迁移前后既有题库与学习记录不丢失。
- 浏览器端验证桌面及小屏幕布局、键盘焦点、窗口尺寸约束和图片加载。关键流程需使用截图与交互结果验证，不能只以构建成功作为完成证据。
- 最后通过发布产物的标准插件安装流程验证，不仅在开发源码路径中验证；兼容和缺失依赖错误需给出可操作提示。

## Out of Scope

- 修改或 fork DSH 核心、重新实现 Agent 引擎、技能加载器、插件市场或凭据管理。
- 一次性复制 Better Sidebar 的文件编辑、浏览器、终端和 Git 功能。
- 多设备同步、云账号、协同学习、公开服务部署和任意远程 iframe 集成。
- 第一版完整的多实例独立题库、全功能角色编辑器、在线 Skill 商店和复杂工作流编排。
- 未经指定重新处理所有讲义、上传个人 PDF 或图文题库到公共 GitHub。
- 自动升级其他插件或通过版本豁免跳过不兼容检查。
- 当前规格编写阶段直接更改运行中的学习应用或宣称窗口功能已实现。

- Better Sidebar 兼容性依据已安装 0.24.1 的公开类型声明核对；最终需要运行集成验证。版本支持说明见 [发布记录](https://github.com/omdsh-dev/DSH-better-sidebar/releases/tag/v0.24.1)。
- 用户既有多插件发布仓库为 [my-dsh-plugins](https://github.com/lvyangyan12q/my-dsh-plugins)。这不等于 Issue 跟踪器已经配置。
- 用户已选择本地任务文件，11 个任务按依赖关系保存，每个任务的状态为 ready-for-agent。没有远程父 Issue，不在 PR 中生成虚假的关闭引用。

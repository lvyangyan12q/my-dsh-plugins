# 学习课堂

DSH 的个人学习插件：从一个本地**知识文件库**开始，为每门课建立一个学习空间，课堂里同时容纳课程目录、讲义、个人笔记与老师对话。

本版本（工单 01、02、03、04、05、07、08）交付课堂骨架、知识库接入、讲义阅读、笔记编辑与离开保护、真实内嵌老师会话、只读课程脉络与节点导航：

- 侧栏「学习课堂」入口与主面板。
- 首次使用选择一个已存在的本地目录作为知识文件库，绝对路径保存在插件状态里。
- 创建学习空间时，在知识库根下建立同名文件夹：`讲义/`、`笔记/`、`附件/`，并写入默认笔记 `笔记/我的笔记.md`。
- 未选知识库、目录不可访问、目录不可写时给出可操作状态，不把裸异常抛到界面。
- 主面板四区骨架：课程目录、讲义、我的笔记、老师对话；对话区在没有会话时是明确的未连接占位，不伪造聊天。
- 课程目录由 `讲义/` 下的文件推导（`.md` 与 `.html`），按文件名排序，frontmatter 的 `order`/`title` 可覆盖；不写清单文件。
- 点击 Markdown 讲义在右侧排版阅读（标题、列表、表格、代码、引用、数学公式）；渲染只使用类型化块模型和 React 文本节点，原始 HTML 降级为纯文本。公式支持行内 `$...$` 与独立 `$$...$$`，由宿主公开的 KaTeX 渲染器呈现；围栏代码和行内代码里的美元符号保持原样，不会被误认为公式。宿主未提供该公开渲染器时明确显示 TeX 源码并标明“尚未排版”，不伪造公式外观。
- 当前讲义按学习空间保存在插件状态里，重新打开回到上一节；讲义被外部删除或改名时提示并给出重新加载目录的出口。
- HTML 动态实验采用声明式 spec：文件里只有惰性 JSON，课堂用固定可信 runtime 在沙箱 iframe 中渲染参数、读数与折线/柱状图；不执行模型提供的 HTML/CSS/JS。旧式任意脚本 HTML 实验明确不执行并提示重新生成。
- 「我的笔记」直接读写学习空间 `笔记/` 下的 Markdown：默认打开 `笔记/我的笔记.md`，可切换到该目录下其他 `.md`。
- 「编辑 / 预览」共用同一正文：预览直接渲染编辑器里的当前内容（包括尚未保存的修改），不会读第二份副本；切回编辑不改变文字。预览沿用同一套类型化 Markdown 块模型与同一安全渲染器，原始 HTML 不会进入 DOM；笔记里的 `$...$` / `$$...$$` 公式和讲义走同一个宿主 KaTeX 渲染器。
- 编辑后防抖自动保存，另有显式「保存」；保存中、已保存、失败三态始终可见。所有保存进入同一串行队列：前一次未完成时后一次等待，不并发写同一文件。排队保存执行时会取该文件当前已知的最新版本，前一次成功不会让后一次与自己的成果产生伪冲突。
- 每次保存携带读取时的内容哈希版本。外部编辑器改过同一文件后保存被拒绝，界面并排展示「我的编辑（未保存）」与「磁盘上的版本」，再由用户选择「重新加载」或「用我的覆盖」，绝不静默覆盖。磁盘版本尚未读出或读取失败时，「用我的覆盖」保持禁用，避免在没看到对方内容时覆盖；失败可重试读取。若「重新加载」失败，冲突保留并可重试比较；比较成功会建立仅限显式覆盖的读取身份，普通保存仍被冲突拦截，只有「用我的覆盖」实际写入。覆盖成功且仍是当前视图时，该读取 epoch 会提升为普通保存身份，之后继续编辑的自动/显式保存使用覆盖写下的新版本，不会因「没有成功读取」被拒绝。
- 覆盖本身失败（无权限、目录被删、磁盘错误）时仍保留我的输入并说明原因，可以再次处理；不会只留下一个已变空的编辑器。
- 每次编辑都会**同步**写入当前页面的草稿（sessionStorage；失败时退回内存），不依赖防抖、React cleanup 或异步 HTTP；pagehide 只是补充，不是唯一路径。浏览器刷新/关闭时若草稿只能留在内存，页面级 `beforeunload` 会要求确认；该 guard 不随课堂组件卸载而消失，只有风险清空（保存、放弃或成功持久化）才解绑。这不能保证进程被强杀等所有情况都能保存。
- 切换笔记文件、切换学习主题或离开课堂时，未完成/失败的输入会先尝试保存，并同时按「主题 + 文件」留一份可恢复草稿；重新进入时明确提示「已恢复上次未保存的草稿」，可「保存草稿」或「放弃草稿」。草稿记录它基于的磁盘版本：若磁盘此后被外部修改，恢复时直接进入双方内容比较的显式冲突，不会把旧草稿绑定到新版本后自动保存。草稿还带单调 revision，且 revision 时钟在页面内跨挂载共享、清理草稿后不回退：旧的保存失败晚到时不能覆盖切走或重进后留下的更新草稿；卸载后旧回调也不再获得写入权限。内存-only 风险是页面级状态，切换学习主题后仍保留提示，不会因新主题加载而消失。草稿键是「学习空间 UUID + 空间内笔记路径」：空间 id 创建时随机生成，切换知识库会清空已登记空间，因此不同知识库的草稿不会互相绑定。
- 保存完成回调按「文件 + 读取 epoch」归属：旧请求成功只更新该文件的最新版本账本，不会把新视图的 loading 空正文写成 dirty 或再排一次自动保存；若保存恰好在一次读取期间完成，读取会重读新版本而不是应用旧快照。没有成功读取身份的请求不会用版本 map 复活保存。
- 切换文件时立即清空上一文件的正文与版本；若新文件读取失败，编辑器不会把旧文件的正文写进新路径。草稿正常存于浏览器 sessionStorage（同一标签页内有效）；写入失败（配额/隐私设置）时退回同一页面内跨挂载共享的内存草稿，并明确提示「只保存在内存，关闭或刷新页面会丢失」，不会悄悄吞掉切走前的文字。草稿不写插件状态、不另建第二份笔记文件。
- 插件自己的笔记写入路径：`writeVaultText` 先过 `assertVaultWriteAllowed`，`笔记/` 只允许 `note-save` 这个 actor 写入。老师生成讲义/实验使用独立的 `讲义/` 写入路径，不写 `笔记/`。**这只覆盖插件内的写入路径，不是对老师会话的全局写保护**，见下节。
- 老师对话是**真实 DSH 会话**：显式「打开老师会话」时用公开 `sessions.create({ cwd, agentPreset: 'standard' })` 创建，会话绑定按学习空间保存到插件状态（`session-open`）。
- 课堂内嵌走公开组合：自有 `sessions.retain(id, { source: 'personalLearning' })` 引用 → 自己命名的 `learningClassroom.teacherSession` 子 seat 由框架 `SessionProvider` 包裹 → 在子 seat 内渲染 `conversation.content` 的 `embedded` 变体。原生输入、流式输出、工具呈现、Stop、提问与审批都由该 Factory 负责，插件不导入私有 Chat 组件、不重画消息列表、不调用会跳转原生页面的 `openSession`。
- 离开课堂、切换学习空间或引用失败时只释放引用，绝不调用 `cancel`；Stop 只能由用户点原生停止。切回同一空间会重新 `retain` 同一会话。
- 会话不可用、创建失败或保存绑定失败时显示真实错误与「重试」，不降级为假聊天；页面上的可编辑聊天输入框始终只有内嵌会话这一个 composer。
- 「课堂 / 脉络」在主内容区切换：脉络读取学习空间里的 `脉络.canvas`（JSON Canvas 1.0），只读渲染文本、文件、链接、分组节点和带标签的有向边；切换视图不覆盖讲义与笔记选择。画布是 pan/zoom 视图：滚轮或放大/缩小按钮改变缩放，拖拽平移，重置回到 100%。
- 边标签决定关系语义：以「先修 / 前置 / prerequisite」等开头的是先修，以「组成 / 包含」等开头的是组成，以「应用 / apply」等开头的是应用，其余为相关；三类关系用不同颜色与线型区分，并有图例说明。知识关系不是有向无环图，允许环；指向自身的边明确标记为「自引用」。
- 箭头严格按 JSON Canvas 1.0 的 `fromEnd`/`toEnd` 渲染：`fromEnd` 省略默认 `none`，`toEnd` 省略默认 `arrow`；显式写 `none` 才去掉该端箭头。`fromSide`/`toSide` 决定边从节点的哪一侧离开/进入（自引用边也遵守）。插件只按标签补充关系说明，不反转 `fromNode`→`toNode` 的方向。
- 点击文件节点：讲义节点切回课堂并打开那一节，笔记节点在「我的笔记」里打开对应文件。文件节点支持嵌套章节（如 `讲义/第一章/01-条件概率.md`）、已通过「关联现有讲义」接入的课程文件，以及标准 `subpath` 字段或 `file#…` 里的 `#标题`/`#^块id` 片段；片段只在 Host 于真实 Markdown 里找到对应标题或既有块后才算可打开，并切换到讲义/笔记的真实位置。
- 目标不存在、路径越界、片段不存在或不是本空间的讲义/笔记/已关联讲义时给出逐节点提示，不假装打开；缺失片段标记为「锚点不存在」，不会在渲染 DOM 里伪造锚点。
- 画布缺失或格式非法（未知节点类型、缺少必需字段、非法尺寸坐标、边引用不存在的节点等）时整体报错，不渲染半张图；非法画布不会被写入插件状态。
- 插件内没有新增节点或连线的编辑入口；脉络始终显示绝对文件路径，并提供 `obsidian://open?path=…` 的「在 Obsidian 中打开」动作，编辑交给 Obsidian。外部修改后可用「刷新脉络」重新读取同一文件。
- 原生打开先探测公开的 DSH `remote.session.canOpenWorkspacePath`/`openWorkspacePath`。只有宿主明确报告可用时才显示「用系统默认应用打开画布」按钮；不可用或被拒绝时显示真实原因、绝对路径与 Obsidian 替代，不渲染无效按钮，也不把未验证的能力写成已交付。
- 脉络文件节点路径按 JSON Canvas 与 Obsidian 的约定使用知识库相对路径（如 `概率论/讲义/01-样本空间.md`），也接受空间相对写法（`讲义/01-样本空间.md`）；两种写法都会在 Host 侧重新做知识库校验。
- 重启宿主后，知识库选择、学习空间列表、当前空间、当前讲义、当前笔记与会话绑定仍然保留。
- 每个学习空间记住上次打开的笔记文件与讲义阅读位置（滚动偏移）；重新进入时按该主题恢复，某个主题的文件被改名或删除时只影响该主题，不会把偏移套到别的文件。阅读位置和笔记选择都是导航状态，讲义与笔记正文始终只在知识库文件里。
- 「学习接续」在讲义区显示当前目标、上次阅读位置和已保存的小结，并可一键回到上次阅读位置。点「编辑小结」后可显式保存「本次小结」与「下一步」，写入该学习空间的普通 Markdown 知识文件「学习小结.md」（Obsidian 读同一份）；两段用成对 HTML 注释标记分节，正文里的任意 Markdown 标题、列表和代码块原样保留，不会被当成小节边界；标记外或手写旧文件里的其他内容会作为额外文本保留，并在下次保存时原样写回，不会静默删除。保存始终使用草稿写入时的基线版本：外部改过同一文件时拒绝覆盖并保留草稿，不会用刚读到的版本把外部修改静默盖掉。未保存草稿复用笔记的 sessionStorage/内存草稿机制，逐字同步落草稿，刷新或重新挂载后恢复并明确提示，恢复不等于自动保存；切换学习空间时草稿按主题保留，迟到的保存结果不会写进另一个主题。加载、保存、取消与重新加载按主题分配操作序号并用草稿 revision 做 CAS：在途请求的迟到回包不会覆盖新输入、重开已取消的编辑或删掉更新的草稿。插件不根据浏览或一次答对推断长期掌握，也不提供自动复习排程。

尚未完成：真实宿主整体验收（工单 09/10）与真实模型生成/审批证据；自动化替身不能替代真实浏览器验收。

## AI 写权限边界（未验收前按下列边界理解）

- 插件内的笔记写入只有 `writeVaultText`，`assertVaultWriteAllowed` 拒绝非 `note-save` actor 写入 `笔记/`；老师生成工具使用独立的 `讲义/` 写入路径，不写 `笔记/`。这条守卫**只约束插件自己的写入路径**。
- 老师会话是标准 DSH Session，它的通用文件/终端工具由宿主运行时直接执行，**不经过本插件的 `笔记/` 写入守卫**；本插件也没有为它安装权限插件或工具路径规则。
- 因此「AI 不修改我的笔记」在当前版本是**教学约定，不是强制权限**。插件对话区不会写入笔记，但老师会话若被要求改写文件，宿主工具仍可能写入学习空间目录，是否被拦取决于该 Session 的审批与权限模式。
- 真实安装验收必须分别记录：标准 Session 通用文件/终端工具的实际写权限与审批表现，以及插件专用写入路径的拒绝结果。不得用提示词或本 README 的约定替代权限证据。

## 生成发布、实验隔离与支持范围

- 老师生成工具只接受真实绑定到学习空间的 Session；主题完全由执行 Session 决定，工具参数没有 `spaceId`/`sessionId`，未绑定、一对多或跨主题路径都会被拒绝。空间根目录或讲义路径中的符号链接/目录联接同样拒绝。
- 生成文件先写隐藏 staging，再用 hardlink 无覆盖发布；同名文件不覆盖，取消/失败只清理自己的 staging。**只支持能够 hardlink 的本地文件系统**：不支持时明确失败（`generation-publish-unsupported`），不退化复制、不产生可见半文件、不删除竞争出现的外部文件。
- 与笔记保存一样，这**不是跨进程锁**：Host 只在单进程内串行，发布前做 canonical folder、`dev:ino` 目录身份和 staging `realpath` 检查。Node.js 的 `fs` 没有 `dirfd`/`openat`，无法承诺抵抗本机恶意进程在检查与 `link` 之间原子替换祖先目录；支持范围是**本地可信文件系统 + 非恶意外部进程**。若要求抵抗恶意文件系统替换，应另行收窄或关闭生成能力，不能仅靠再查一次掩盖。
- 动态实验是**声明式数据**：`.html` 文件只含固定外壳、来源和惰性 `<script type="application/json">` spec，不含模型 HTML/CSS/JS。Host 只接受受 schema 约束的参数、读数、折线/柱状图与受限数学表达式，并把表达式编译成白名单 AST（数字、参数、四则/幂、括号和白名单函数；无 eval/Function、无属性访问、无字符串、无任意调用），节点/深度/采样有硬限，非有限结果明确报错；参数默认值必须落在 `min + 整数×step` 的网格上，避免浏览器 range 吸附后显示值与求值不一致。模型无法通过标题、标签或 spec 字段注入标签或脚本。
- 课堂读取 spec 后，用**固定可信 runtime** 在 `iframe sandbox="allow-scripts"`（无 same-origin、forms、popups、top-navigation）中渲染；spec 只以 `JSON.stringify` 转义后的 JS 字面量注入（`<`、U+2028/U+2029 均转义），runtime 不使用 `innerHTML`、不 postMessage、不 fetch/联网、不读 `location`。iframe 的 `allow-scripts` 只运行这段固定代码；这个边界只覆盖课堂内嵌渲染，不是对任意打开方式或整个 DSH 的通用隔离。
- Chrome 会忽略通过 `<meta>` 声明的 CSP `sandbox` 指令，因此同源隔离来自 iframe 的 `sandbox` 属性；CSP 继续限制资源加载与网络。实验文件若在课堂外直接打开，不继承课堂 iframe 的沙箱。
- **安全收缩（明确披露）**：旧式任意 HTML/脚本实验不再执行，原文件保留在原位置，界面显示路径和“请让老师重新生成声明式实验”。这是为关闭脚本自导航/联网而做的有意不兼容，不是静默丢失文件。真实模型生成、审批与 Chrome 注入负例由真实验收入口记录；本 README 不把源码完成、自动化替身或构建通过当作通用隔离或抗恶意文件系统的证明。

## 存储与文件

- 存储域：`learning_classroom` v1，只保存知识库根路径、学习空间与会话绑定、当前学习空间、当前讲义与当前笔记选择、每个学习空间的阅读位置（讲义路径+滚动偏移）；讲义、笔记、小结与脉络正文永远是知识库里的文件。旧状态没有阅读位置字段时按「未记录」加载，不拒绝已有空间。
- 每个学习空间只绑定一个老师会话：`sessionId` 存在空间记录里；旧状态没有该字段时读作「未打开」，不会被拒绝。
- 不读取也不写入已删除的旧个人学习存储域。
- Host 侧提供唯一 HTTP 入口 `/api/learning-classroom`：`GET` 读取状态，`POST` 发送带 `action` 的命令。未知 action、未知字段、非 JSON 请求一律拒绝；所有命令在同一队列串行执行。
- 讲义命令：`lecture-list`（从文件系统推导目录）与 `lecture-read`（读取 Markdown 正文或返回 HTML 占位）；讲义路径限制在当前学习空间的 `讲义/` 目录内。
- 笔记命令：`note-list`、`note-read`、`note-save`。`note-save` 必须带读取时版本，版本不符返回 409 业务冲突；只有显式 `overwrite: true`（用户选择「用我的覆盖」）才允许替换外部修改。`note-select` 只记录当前主题上次打开的笔记路径，不写正文。
- 学习接续命令：`summary-read` / `summary-save` 读写主题根目录的 `学习小结.md`（带版本与原子替换）；`position-save` 记录当前主题讲义路径与滚动偏移。两者都只改导航状态或知识文件，不产生掌握度或复习数据。
- 脉络命令：`canvas-read` 读取当前学习空间的 `脉络.canvas`，结构校验在纯逻辑模块里完成；文件节点目标在 Host 侧逐个解析成 `ok / missing / missing-fragment / outside / unsupported`，支持嵌套章节、已关联讲义和真实标题/块片段；命令失败时不返回任何节点。
- `session-open` 只记录浏览器已创建的真实会话 id，不在 Host 侧另造会话。
- 所有文件路径在 Host 侧重新校验：必须是知识库根内的相对路径，拒绝 `..`、绝对路径、盘符、UNC 与越界符号链接；越界报错而不是静默修正。笔记路径还必须位于所属学习空间的 `笔记/` 下且是 `.md`。
- 笔记写入先在同目录写隐藏临时文件，再用一次 `rename` 原子替换目标，成功后才返回；超过大小上限、版本过期或路径/目录校验失败都在落盘前拒绝，原文件逐字保留，暂存文件被清理。
- 所有命令在 Host 边界串行化，同一进程内的并发保存不会互相踩踏；客户端再按面板串行保存。**但这不是跨进程锁**：版本校验（读当前正文并比对哈希）与 `rename` 之间仍有一个 TOCTOU 窗口，另一个进程（Obsidian、同步工具、另一个 DSH 实例）可以在这个窗口内写入，随后被本次 `rename` 覆盖。插件不宣称能阻止这种外部竞争；需要绝对协调时，应由单一写入方或外部版本控制负责。真实外部编辑的常规路径会在校验阶段被识别并转为冲突提示。
- 创建学习空间先写入隐藏的暂存目录，再整体重命名为目标文件夹；同名目录已存在时复用已登记空间或明确拒绝，不留半写结果。

## 开发

```powershell
pnpm install
pnpm build
pnpm test
```

测试使用 `node:test` + `tsx`：Host 侧在真实临时目录上走 HTTP 与落盘断言，客户端用 jsdom 渲染主面板并注入假请求边界、假 Session 服务与假 slot 运行时。

`tests/host-compatibility.test.mjs` 检查包声明能否被真实运行的宿主接受，需要 `DSH_SOURCE`
指向已构建的官方 checkout（未设置时跳过），否则它在 `pnpm test` 中不提供证据。

隔离真实宿主环境（独立 `DSH_HOME`、独立端口、独立知识库，不触碰正式 profile 与 3080）：

```powershell
pwsh -File scripts/isolated-host.ps1 -Action setup  -Root <隔离根>
pwsh -File scripts/isolated-host.ps1 -Action provider -Root <隔离根>   # 可选：复刻正式 profile 的模型路由（无密钥）
pwsh -File scripts/isolated-host.ps1 -Action seed   -Root <隔离根>
pwsh -File scripts/isolated-host.ps1 -Action install -Root <隔离根>
pwsh -File scripts/isolated-host.ps1 -Action start  -Root <隔离根>
```

`seed` 只在**全新主题**上工作：目标主题 `概率论` 已存在（含空目录）一律拒绝且不写任何文件。
整份样例先在知识库根下的私有 staging 目录里组装，最后用一次 `rename` 发布；失败只清理私有 staging，
不会对任何公开路径做删除，也不会覆盖既有主题。

脚本**不处理凭据**：不读取、不复制、不写入任何凭据文件。需要模型时，由用户在隔离宿主的模型设置里自行配置；
正式 profile 的凭据不得被自动搬运。隔离根在验收后应整体删除。
步骤、版本核对与红绿记录见 `docs/evidence/2026-11-10-ticket01-isolated-host.md`。

# 窗口4增量草案：收集、复盘与知识沉淀

讨论稿，尚未发布为实施票。按用户最新澄清，本期只收集和复盘；保留资料供后续优化流程使用，不建立评分、比较或重跑系统。

## 复用路线

窗口4提供入口、材料选择、进度、编辑和真实结果展示；复盘方法复用 co-dev 的 spec-retro，保留规则复用 spec-asset-curation，外部归档/提炼复用 external-knowledge。spec-optimize 留给后续独立优化请求。本轮不复制整套命令编排或清理功能。

## 建议的收集单位

按一次run或用户明确选定的历史任务收集，保留需求与代码的对应关系。是否首期允许失败/中断任务见决策票，不把资料收集自动等同成功案例。

| 材料 | 收集内容 | 边界 |
| --- | --- | --- |
| 需求 | bug、spec/plan/tasks实际存在的文件或章节、确认记录 | 不补造缺失spec，不要求普通bug补全Speckit流程 |
| 代码 | 仓库身份、base/修复commit、分支、变更文件、diff和必要片段 | 不只保存会漂移的分支名；未提交来源记录工作区状态及hash |
| 处理过程 | 每轮方案、原review、定向确认、测试命令/结果/未验项 | 保留原结论及后续处置关系，不改写成统一PASS |
| 会话 | 已绑定fix/review会话ID、必要且授权的增量窗口 | 默认不全量复制历史日志；DSH接入需验证 |
| 复盘 | 结论、依据、适用范围、实际状态、后续行动 | 只补新增内容，缺来源标未知，不创建空报告 |
| 知识候选 | 可复用经验、领域知识、设计取舍及来源 | 项目规则、raw归档、wiki提炼分别记录状态 |

建议在bug-solver保留收集清单与必要快照；当前需求和代码仍由目标项目拥有。是否复制完整代码由用途决定，默认版本引用加选定diff/必要文件，不复制仓库、凭据或全量会话。

## 建议的用户路径

选择run/明确任务 → 查看材料和缺失项 → 生成复盘草稿 → 编辑并保存到项目唯一归属 → 预览知识候选 → 按明确清单执行已选择的归档/提炼 → 查看实际完成、跳过和失败项。

普通保存复盘不触发写外部库、改skill或删除材料。raw归档与wiki提炼允许独立选择，不把归档成功显示成知识已发布。没有新增内容时复用既有结果，不刷新日期制造新记录。

## 应修订旧规格的地方

1. 保留独立窗口、复用Host桥和按需原生复盘会话；不自动新增审核轮次。
2. 知识库解析遵循目标项目政策/显式目标；同时考虑env、Claude/Codex项目配置，冲突明确提示。不能写死旧稿的项目配置优先。
3. 先读取目标库实际导航和规范，不要求固定knowledge-policy.md或固定skill名称。
4. 会话来源方法可以复用；retro_context.py的read会写pending token，bind/read/ack属于执行操作，预览应无副作用。DSH日志必须验证实际格式和身份，不能仅传sessionId就声称已支持。
5. 保留、归档与知识提炼用实际用途决定；本期不引入源文件清理。
6. spec引用兼容窗口3的仓库外绝对路径与none；按实际读取内容记录来源。
7. 挂载按实际pane身份、布局revision和Worktable握手处理，不以固定p4覆盖已有窗格。

## 本期验收候选

能从明确任务得到可追溯材料清单；按实际材料生成复盘且缺项可见；重复处理没有新增时不重复入库；保存失败保留草稿；外部未配置时仍能完成项目内复盘；明确区分项目保存、raw归档、wiki发布。不以质量评分或流程优化效果作为验收条件。

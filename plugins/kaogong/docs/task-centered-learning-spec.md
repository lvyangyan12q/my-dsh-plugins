## Problem Statement

学习者已经在今日任务中确定学习内容，进入课堂却还要新建课堂、填写目标、选择科目和角色。老师答疑又会打开 DSH 会话页，使学习者离开考公插件，在目标、讲义、练习与对话间反复切换。资料库和自由练习藏在折叠项中，不容易发现。

学习者希望把时间用于学习、做题、答疑、复习，而不是管理课堂、会话和证据关联。减少交互不等于取消计划变更、权限审批和完成学习所需的明确确认。

## Solution

今日任务是学习的发起点。一次点击开始或继续，系统自动恢复或创建该任务的课堂，继承目标、科目、知识点及授权资料，不要求再次填写。课堂内完成讲解、示例、当堂检测、专项练习和答疑；答错后直接进入相应补讲或重做。老师使用真实 DSH 会话，正常学习不自动打开会话页。

班主任固定负责整体规划、督学与计划调整；老师固定负责当前任务讲课、答疑和讲评。用户不必配置角色或教师科目。资料库、自由练习与学习进度同级，不再藏入“资料与工具”。

导航为今日、课堂、学习路线、复习中心、学习进度、资料库、自由练习。入口数量不代表七套工作流：今日是默认入口；课堂恢复当前学习任务；其余页面按需访问。完成后的下一步集中出现，不重复堆叠主按钮。

## User Stories

1. As a 备考学习者, I want 打开插件先看到当前任务和继续学习入口, so that 我不用寻找课堂。
2. As a 备考学习者, I want 一次点击进入今日学习任务, so that 我无需重复填写目标。
3. As a 课堂学习者, I want 自动继承任务科目和知识点, so that 老师讲授正确内容。
4. As a 课堂学习者, I want 重复点击或请求重试恢复同一课堂, so that 不会产生重复记录。
5. As a 课堂学习者, I want 刷新和重开后恢复原任务, so that 不必重新选择。
6. As a 课堂学习者, I want 同时查看讲义和老师对话, so that 答疑时不离开学习内容。
7. As a 课堂学习者, I want 在课堂里发送问题并看到真实流式回答, so that 不必跳转 DSH 会话页。
8. As a 课堂学习者, I want 提问自动附带当前知识点和必要的作答依据, so that 不用反复解释背景。
9. As a 课堂学习者, I want 系统只引用已授权资料, so that 不会泄露其他档案内容。
10. As a 课堂学习者, I want 老师按任务固定分配, so that 不必选择角色和教师科目。
11. As a 备考学习者, I want 在今日或学习路线中找班主任讨论安排, so that 整体规划与当前答疑职责清楚。
12. As a 备考学习者, I want 计划建议先预览再确认, so that 减少点击不会变成静默改计划。
13. As a 课堂学习者, I want 缺讲义时看到真实状态和向老师讲解的入口, so that 不会被塞入不相关示例。
14. As a 课堂学习者, I want 教学材料与我自己的笔记分开, so that 不会把个人理解当标准答案。
15. As a 练习者, I want 学完直接进入关联练习, so that 不必再次选题型或填任务号。
16. As a 练习者, I want 正式练习由 Host 判分, so that AI聊天不能伪造成绩。
17. As a 练习者, I want 当堂检测与正式练习成绩区分, so that 小测不会污染正确率统计。
18. As a 练习者, I want 错题直接回对应讲解并能请老师补讲, so that 不用手动寻找知识点。
19. As a 练习者, I want 同一轮草稿和反思在切页后保留, so that 临时离开不会丢答案。
20. As a 复习者, I want 点开到期复习直接开始当前项目, so that 不必再创建课堂或挑选角色。
21. As a 复习者, I want 知识点回忆和错题重做保留不同的完成标准, so that 系统不会虚构掌握率。
22. As a 学习者, I want 总结只填一次且在一个收尾位置确认完成, so that 不会在课堂和计划重复提交。
23. As a 学习者, I want 未达到完成条件时看见具体缺项与直达操作, so that 不会面对不可理解的禁用按钮。
24. As a 学习者, I want 打开课堂、读讲义或聊天结束不自动标记已学, so that 学习记录可信。
25. As a 学习者, I want 资料库和自由练习直接可见, so that 不必展开工具菜单。
26. As a 自主练习者, I want 自由练习不偷偷归入无关今日任务, so that 我的计划依据不会串项。
27. As a 多档案学习者, I want 课堂、会话、资料和草稿按应用实例及任务隔离, so that 不会跨档案串课。
28. As a 学习者, I want 双击、网络重试或多视图同时打开不重复发问, so that 不会产生重复回答或费用。
29. As a 学习者, I want 可以停止生成并处理真实问题和审批, so that 内嵌课堂不会弱化 DSH 的安全控制。
30. As a 学习者, I want 离开页面不自动停止后台任务, so that 页面可见性不改变执行生命周期。
31. As a 学习者, I want 失败时重试同一项操作并保留输入, so that 不必重新开始。
32. As a 学习者, I want 只有主动选择时才查看完整 DSH 对话, so that 日常学习不被导航打断。
33. As a 窄屏或键盘学习者, I want 可切换内容和答疑但不丢状态, so that 学习不受窗口大小限制。
34. As a 学习者, I want 重新安装准确包和冷启动后仍能继续, so that 新版不是一次性文件替换。

## Implementation Decisions

- **增量改造与优先级**：先贯通任务到课堂和内嵌答疑，再清理冗余入口；复用既有任务、课堂、练习、复习、角色服务和真实评分，不重写整个插件。不修改其他插件或 Harness 私有实现。
- **覆盖旧交互的范围**：本规格取代旧体验规格中“学习必须导航到原生会话页＋右侧任务面板”及“角色手动选择”的交互要求；保留原生会话所有权、唯一有效输入所有者、权限审批、真实证据和实例隔离要求。旧规格的评分、复习周期、计划保护与保存依据不变。
- **任务是课堂身份来源**：沿用任务开始接口返回的课堂、轮次和复习引用。前端不另建一套新建课堂流程。服务端按应用实例＋任务身份幂等开始；返回原引用而非每次创建。任务版本用于并发与过期校验，不因计划整体版本变化就无条件生成新课堂。
- **课堂入口语义**：今日学习任务开始后进入插件课堂；练习和复习任务进入对应学习内容并保持插件壳。导航“课堂”恢复本档案最近仍有效的学习任务；无当前任务时提供“去今日学习”，不强塞混合增长率示例、不显示创建目标表单。不抢占或静默开始另一任务。
- **完成任务处理**：已完成任务只读回看或显式重学；新学习尝试不得覆盖原成绩和完成依据。旧独立课堂仍保留为历史可访问记录，不自动猜测任务归属或删除。
- **固定职责而非配置器**：主流程移除角色选择、教师科目下拉、新建课堂和手动课堂列表；保留必要的历史记录入口为次级操作。班主任处理全档案规划督学，老师处理当前教学和复习讲评。不再向用户暴露辅导员选择；已有辅导员会话仅保留历史，不删除、不静默搬运历史消息。
- **会话绑定**：班主任绑定应用实例；老师教学上下文绑定应用实例＋任务＋课堂。现有角色绑定以实例、职责和科目为键，并不天然保证每个任务独占会话。先验证原生公开接口是否支持任务级会话引用；若可用则持久化该引用并恢复。如果现有服务只能返回科目级会话，必须先补公开任务级适配或明确隔离策略并评审，禁止仅在前端伪造任务隔离。刷新、双开视图和切任务不得借当前全局会话猜归属。
- **教学任务去重**：当前任务开始已有课堂引用恢复，但准备受管教学内容每次调用仍可能创建新草稿；补充应用实例＋学习任务/课堂＋本次用户动作的幂等键或等效服务端去重。恢复已有草稿、已提交或结果未知的发送时查询原操作，不能盲目新发；再次主动提问是新动作，不被误去重。
- **分离准备、发送、导航**：现有准备教学任务时打开角色会话的流程拆开。绑定/准备上下文不再自动调用打开原生会话页；学习者点击开始教学、发送问题或请求讲评是明确发起动作。一次动作只提交一次受管教学任务，不新增“准备完后再点发送”这一冗余步骤，也不在挂载、恢复或切页时自动发送。
- **真实内嵌原生对话为技术门槛**：静态核对发现 DSH 已有公开会话保留、会话作用域及 embedded Conversation Factory，且有子代理侧栏的生产先例；优先复用这些公开会话内容、输入及控制能力，保持真实 sessionId、流式消息、工具活动、提问、审批和 Stop。普通标准会话嵌入考公主面板尚未实测，不能据先例直接宣布全部支持。内嵌不等于挂一个模拟聊天框，不读取私有消息缓存，不绕开模型权限，不自行拼接替代原生 Agent 循环。
- **最小能力探针**：先证明在插件课堂内对指定会话发送、流式接收、停止、回答问题/审批、断线恢复，以及输入所有权和多视图隔离。若公开扩展点不足，形成具体缺口与单独公开接口变更申请；后续依赖该能力的切片不宣称完成，不以强制跳转或改 Harness 私有代码兜底。
- **课堂布局**：桌面采用讲义/练习主区与老师答疑区；窄屏在同课堂切换内容与答疑，保持输入草稿、当前位置及作答。练习可复用原组件嵌入课堂，不要求为了做题跳到顶层自由练习。顶层自由练习用于自主练习，不混入任务上下文。
- **上下文最小化**：答疑携带服务端解析的任务、课堂、知识点和必要题目引用；错题讲评在正式提交后才暴露答案。不允许客户端自行上报“正确”作为正式判分依据。老师生成的教学内容有来源标注和校验状态，不自动当成完整权威讲义。
- **内容正确性为发布前置条件**：当前示例存在区间排除错误、缺人口权重的人均收入混合题、无依据的耗时/占比承诺，须修正或下架。按稳定知识点匹配内容，不能仅凭模糊标题把不同任务视为同课。没有教学资料时可以真实请求老师讲解，但不能伪装已有资料。
- **保存与完成语义**：浏览、页面渲染、打开检测和答对一次均不标记“已读/已学/已掌握”。学习进度由真实证据投影；学习者总结与完成确认集中一次，后端核对证据并幂等回写任务。保留计划调整预览确认、复习入队选择及原生权限审批，不用自动勾选来减少点击。
- **持久化与恢复**：持久化当前任务引用、课堂绑定、教学任务/会话引用及必要草稿；UI 选择状态和证据分离。保存失败就地提示、保留草稿、可重试，过期响应不覆盖切换后的课堂。兼容扩展须验证旧记录读取及旧程序回写风险，不能仅因可选字段便笼统宣称可逆。不可逆业务迁移仍需影响预览和确认。
- **交互预算**：已有今日任务进入课堂只需一次点击，零目标/科目/角色填写；课堂答疑一次发送，不强制二次发送或页面跳转；当前任务练习无需重选条件；无影响的导航/保存不添加确认。危险操作和真实业务确认不计入可删除冗余。
- **发布**：独立新版本包由插件管理器安装，profile 绑定准确包，保留旧包和数据回退路径。源码测试、构建、准确安装包与真实模型验收分开记录；不再只复制安装目录脚本宣称更新完成。

## Testing Decisions

- **主 seam（待用户核对）**：准确安装包运行于现有 3080，驱动“今日任务 → 插件课堂 → 教学/提问 → 练习 → 错题补讲 → 收尾 → 到期复习 → 重开恢复”的学习者路径。以可见界面、真实网络行为、持久记录和原生会话身份为断言，不测试组件内部状态或靠源码字符串当验收。
- **业务与渲染回归**：复用既有 jsdom 页面测试、任务开始/恢复测试、课堂完成测试、练习判分与复习领域测试。检测一次点击、无重复表单、同层导航、无自动跳转、只有一个当前主动作，以及无资料/无任务的真实空态。
- **Host 集成**：真实存储边界验证并发 start/重试仅产生一份绑定；课堂和轮次自动关联；计划版本冲突；跨档案/任务拒绝；失败重试不重复发送、计分或确认完成。客户端 fetch stub 不能替代这些证据。
- **会话能力探针**：用真实公开接口与实际 Agent 运行验证发送、流式、工具状态、提问、审批和 Stop；切换任务/双视图不会向错会话发问；恢复原消息与输入草稿；没有第二个争用同会话输入的 composer。模拟响应只用于错误分支测试，不作为可内嵌的证明。
- **恢复**：切页、刷新、断线重连、冷启动、准确包重装后，任务、作答、总结、会话身份与待审批状态保持。离开页面不等于停止运行，Stop 不等于任务完成。
- **内容校验**：用可复算的算术数据锁住区间与加权结论；题目条件充分、来源明确；无关任务不渲染示例；检测结果不写入正式正确率或掌握率。
- **视觉与可访问性**：真实桌面/窄屏检查、键盘操作、中文输入、焦点恢复、滚动与布局不遮挡输入/审批/停止控件。截图可证明导航和布局，不能证明评分、保存或模型调用真实。
- **验收记录**：记录包版本与哈希、宿主版本、测试命令/结果和未通过项。已有 42 项课堂/导航测试只是历史基线，不代表本规格通过。

## Out of Scope

- 重写通用工作台、改动其他学习插件或 Harness 私有代码。
- 删除历史课堂、会话或资料；把旧全局数据自动归入新档案。
- 自动调整计划、自动打卡、以聊天结束或自评产生掌握率。
- 新模型选择器、新角色管理器、新的提示词配置中心。
- 一次性生成全部考试课程，或把当前两份示例当完整教学体系。
- 对外正式发布、远端创建/更新 PR、合并代码；本轮只交付规格和 PR 正文草稿。

## Further Notes

本规格基于用户已确认方向，未进行额外需求访谈。测试主 seam 已提出，但尚待用户核对；ready-for-agent 是本地 triage 标签，不代表会话内嵌技术探针已通过或全部切片可并行实施。

建议落地顺序：A 任务和会话身份/公开内嵌探针 → B 一键任务课堂与固定角色 → C 真实课堂答疑及单次发送 → D 课堂练习、强化与统一收尾 → E 同层导航和复习直达 → F 正确内容、恢复、多视图与准确包验收。B 的任务绑定可在 A 调研期间独立验证，C 必须等待 A 通过；D 依赖 B/C，F 对全部切片作最终门禁。当前仅规划切片，尚未发布实施子票。

# 学习与复习改版：当前实现评估

日期：2026-11-04。核对基线：Git HEAD `6c70562ecee8f92afca4db956806444024d4631f`，源码包 `0.3.1-alpha.2.1`。这是源码、接口和已有测试的静态核对，本轮未重新运行发行测试或实装页面，不宣称这些测试当前通过。

## 结论

采用“保留领域底座，重组前端页面，补充学习路线和知识点复习”的增量改造。无需另写一个考公插件，也不宜把原型 HTML 直接接上几个接口作为正式实现。原型决定可见交互，现有领域记录继续作为真实数据来源。

## 关键边界

1. 现有计划任务完成与课堂完成是不同记录，已经有串联，但非一个天然跨领域原子事务。新增“完成并加入复习”必须定义重试身份和恢复步骤；不要因为 UI 只有一个按钮就声称一次保存绝对原子成功。
2. 计划开始接口当前按科目创建课堂/练习，未传递稳定知识点身份。因此路线点击具体知识点不能直接原样复用现有按科目发题路径；需增量传递并校验该身份，缺题仍沿用明确拒绝或显式放宽条件，不静默换题。
3. 现有错题库是历史查阅入口，显示旧答案本身并非违规；新需求是将复习交互与查阅分开，并限制复习响应提前揭示，不能破坏用户查看已提交历史的能力。
4. 课程覆盖与练习正确率必须分别计算。大纲节点、资料条目、课堂完成、任务完成均不天然等价，需由明确关联产生学习状态；无法确认的旧关联保留未知，不迁移成已学。
5. `production-host.ts` 会依据命令挑选资料与题库授权，不能仅向内部 registry 加接口就认为新路径已支持授权。新增路线、知识点复习和复习揭示须同时核对来源选择、撤销与模型工具边界。
6. 旧课堂确认要求与直接计划任务完成要求并不完全相同，已有测试分别覆盖部分作答与全部作答。统一 UI 不应顺带静默放宽或收紧这些条件，应按任务规则展示缺项并保留既有合同。

## 实施顺序

1. **具体任务贯通**：共用任务开始/恢复编排，今日卡片直达；建立统一收尾与完成依据展示，先保持现有领域记录与评分。
2. **知识点身份和路线**：增量建立科目/章节/知识点与课堂/任务关联，提供学习状态投影及周安排；保留未映射历史。
3. **复习领域补齐**：保留错题规则，补知识点主动回忆、统一队列读模型、复习阶段揭示和复习草稿。
4. **四页与课堂视觉整合**：按批准原型完成今日、学习路线、复习中心、学习进度及窄屏；保留次级功能入口。
5. **准确包验收**：检查完整学习复习链、失败恢复、历史数据、二档案、资料撤销和原生课堂，再发布新版包。

这是依赖顺序建议，不是已完成工单；不据此启动正式实例或覆盖已安装包。

## 测试资产与必须新增的断言

- `standalone-host.test.mjs` 已包含计划确认、同任务重试、课堂回写、错题入队、历史保留、二档案和真实评分等公开行为用例，可在同一入口扩展。
- `task-resume-page.test.tsx`、`study-plan-page.test.tsx` 已覆盖任务续作和计划页面，可扩展今日/路线共同入口，避免各页面重复造业务逻辑。
- `error-review-page.test.tsx` 明确断言首屏显示旧答案：保留历史模式测试，另加复习模式提交前未揭示及 Host 响应不携带答案的测试。
- `practice-rounds.test.mjs`、`plan-tasks.test.mjs`、课堂和原生测试继续作为既有合同回归；不得为使新 UI 测试通过删掉幂等、归属、原题和确认约束。
- 新增：无错题也能知识点复习；自评不产生客观成绩；复习草稿跨页恢复；旧页偏好映射至新导航；完成成功但入队失败的重试不重复完成；新增来源授权路径撤销有效。

## 复写还是调整

- **复用**：领域存储与档案身份、真实练习、成绩和历史、计划调度、原生会话接入、资料与权限。
- **重构/重做页面**：导航容器、今日入口、路线展示、复习中心、任务收尾、课堂右栏。
- **增量新增**：明确知识点关联、知识点学习进度投影、主动回忆复习记录、统一复习读模型及必要的恢复编排。
- **不采用**：整插件重写、平行维护两套业务、把 Open Design HTML 当真实业务代码、为匹配原型批量重建用户数据。

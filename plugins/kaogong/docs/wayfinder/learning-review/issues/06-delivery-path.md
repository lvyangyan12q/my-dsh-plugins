## Question

前面的业务与恢复合同明确后，如何拆出可独立验收的纵向实施切片、避免两套业务并存，并确定旧页面撤换、新包安装与回退门槛？

初始路径假设（不是已批准实施工单）：先具体任务继续与收尾，再知识点关联/路线，再知识点复习与错题模式，再四页整合与准确包验收。前置数据合同可能使某些工作需合并或调整次序；关闭本票时必须给出最终顺序及依赖理由，不能机械按页面拆分。

必须继承既有公开 Host/模型工具、原生课堂、页面确认和准确包无 Worktable 验收边界；明确旧测试保留/变更，二档案、来源撤销、部分失败恢复及原记录保护。固定实施时实际宿主提交与版本，静态评估不是兼容证明。

关闭需要：与用户核对可交接的切片顺序、每片外部可观察结果、迁移和回退范围及验收门槛。输出是实施决策与后续工单输入，本地图不安装、不发布。

## Resolution

2026-11-05：用户已在评审八片拆分后要求生成 tickets，并调用 implement-spec；本次进一步确认完成和导航合同。交付顺序采用已发布实施图：01→02→04→05，03 可独立实施，03/05→06→07→08。先从01窄路径提取共用开始/恢复，03保留既有入口独立验证；各片随流程替换页面，不保留第二套领域服务。

每片沿批准的 Host/页面/Native 边界验证。08必须准确包独立安装，覆盖无工作台完整闭环、共存隔离、重启/重装和原记录保护；固定实际宿主提交与包哈希。新元数据增量保存，回退仅恢复本轮插件和配置，不覆盖新增学习记录。正式3080由用户启动，本轮不推送或公开发布。当前alpha.3运行时/声明问题是待解决验收门槛，不是新一轮业务批准请求。

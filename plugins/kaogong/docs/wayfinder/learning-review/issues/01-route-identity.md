## Question

学习路线是否以现有科目/章节/知识点大纲为主，并将讲义挂接其下？怎样定义可学、在学、已学、待复习和学习覆盖分母？同一知识点有多份资料、多次课堂或已学但复习失败时分别如何显示？

现有事实：分类树存在，计划任务没有明确知识点键，课堂和题目主要使用知识点文本；有限别名比较不是完整身份系统。当前评估已定位这些差异，无需把事实查询转交用户。

建议讨论的口径：大纲为主、资料为来源；本人确认完成且有明确关联才标已学，待复习叠加显示；无资料和旧记录未映射分别提示，不根据标题猜测完成。讨论应决定稳定身份、资料变化/旧记录归属策略及分母口径，而不是直接写新表。

关闭需要：学习对象及状态词义、三个边界例子的用户反馈、明确关联/未知关联处理和对产品规格的修订。此票不交付路线页面。

## Discussion

2026-11-04 用户选择“按此口径（推荐）”：学习路线以现有科目→章节→知识点大纲为主；讲义挂到对应知识点；缺资料明确提示；已确认完成的学习才计入已学。这部分已确认，不重复询问。

本票已由 codex 认领。尚待核对三个边界例子：同一知识点多次学习是否只计一次覆盖；已学后复习失败是否保留已学并叠加待复习；覆盖分母是否包含大纲中缺资料的知识点。稳定身份和旧记录映射沿用实现评估建议，不能用显示标题猜测历史完成。

## Resolution

2026-11-04：依据用户批准第二版原型、明确选择大纲为主及“只有确认完成才计入已学”，并在用户要求继续后核对批准原型实际代码，关闭本票。上面的“尚待核对”是核对原型前的过程记录，不再构成待用户重新回答的问题。

- 原型 `subjectStats` 按章节知识点节点计数，`covered = learned + due`，分母为全部节点。因此沿用按明确知识点去重的覆盖口径；多份讲义或重复学习不增加分母/分子；缺资料不从大纲分母悄悄移除，另显示资料可用性。
- 已确认完成学习的知识点保持学习覆盖；后续复习失败改变复习状态和下次安排，不删除原完成事实。待复习是复习维度，可与已学并存；在学及未学不计入覆盖。覆盖不是掌握率。
- 原型 `createReviewForPoint` / `completeReview` 会直接写 learned，这是演示状态简化；正式实现服从用户更明确的要求：仅入队、仅复习或自评记住，不能把未确认学习的知识点标成已学。
- 知识点采用明确、稳定的身份，讲义、任务和课堂关联该身份；显示名称变化不改历史归属。旧记录仅在已有明确关联或用户确认映射后参与投影；未映射单列，不从任务标题猜测完成。具体字段和存储迁移在实施切片里设计，不批量改写原记录。
- 本票三个例子的依据来自用户已认可原型与补充口径，不伪称用户逐条另行回答。纯演示行为与明确补充要求冲突时采用后者。

验证入口：重复学习同一点覆盖不增加；已学后复习失败仍覆盖但待复习；缺资料节点仍在分母；未知映射不计已学；入队不得完成学习。后续由公开 Host/页面测试证明，当前仅完成决策。

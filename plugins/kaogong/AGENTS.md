# 考公开发约定

开发工作目录为本文件所在的 plugins/kaogong，Git 仓库仍是上层 my-dsh。入口见 docs/README.md。开始实施前读取 docs/HANDOFF.md、docs/spec.md 和 docs/tickets/README.md；处理资料和目录变更时还须读取 docs/migration.md。

本轮目标是完全独立于工作台的考公学习闭环。当前 rc.3.7 仍依赖工作台，只是旧适配基线，不能把它的历史验收当作独立版完成。按工单依赖推进，状态随真实证据更新。

- 源码、现行规格、工单和脚本在本目录维护；共享工作台/Harness文档只保留必要引用。
- 原生 Harness 通过公开接口接入，原生源码和共享依赖目录保持原样。构建使用本目录自有或隔离的物理依赖，避免安装器穿过共享 junction。
- 真实资料、题库快照、解析结果、凭据及私有备份仅本地保存。迁移前更新 Git 忽略和 npm 发布白名单，核对 Git 暂存清单与发行包内容。
- Windows 清理先逐项核对绝对路径，再用 lstat 不跟随链接清点，非递归移除链接，复扫证明零链接后才删除临时检出。不得直接让 Git 或递归删除进入带共享 junction 的目录。
- 迁移复制、哈希核对和引用验证在先；独有或不能判定的内容归档，旧有效资料和回退包保留。已接入资料的证明不能用全局字符串替换重写。
- 原题、选项、答案、评分快照及当前学习记录保留；旧全局计划/错题/会话不自动接管。AI建议经页面确认才生效。
- 根仓库已有用户未提交改动不纳入本轮；按具体路径暂存，不使用整个仓库的 git add/reset/clean。
- 最终验收安装准确发行包，在无工作台的 DSH rc.3 中走完整用户路径；构建、源码测试、原型均不能代替真实闭环。
